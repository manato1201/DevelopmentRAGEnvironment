# 連携の同期の統制（許可リスト・プレビュー・自動同期・ユーザーごとの接続）

2026-10-09追加。連携（Jira / Backlog / Googleカレンダー / Drive / Gmail / Notion）が、いらないデータで知識ベースを汚さないようにするための仕組み。

## 全体像

| 取り込み先                               | 使う接続                        | 書き込み先の索引                         | 誰が操作できるか                                                            | 許可リスト                           |
| ---------------------------------------- | ------------------------------- | ---------------------------------------- | --------------------------------------------------------------------------- | ------------------------------------ |
| 共有namespace（`shared:…`）              | デプロイ全体で共有する1つの接続 | 共有の索引                               | ナレッジ登録権限者（admin / editor）。editorは自分に許可されたnamespaceだけ | **必要**（管理者が許可したものだけ） |
| 個人用namespace（`personal:<自分のID>`） | **自分専用の接続**              | 個人用の索引（他の人からは検索できない） | 本人だけ（ゲストは不可）                                                    | 不要                                 |

- 公式MCP（Notion・GitHub・Slack・Linearなど）はナレッジに保存せず、チャットのたびにその場で読むだけ。接続は共有（管理者）と自分専用の2通りがあり、同じサービスを両方持っている場合は、本人のチャットでは自分専用が優先される。

## 1. 同期前のプレビュー

- すべての同期（Gmail・カレンダー・Drive・Jira・Backlog・Notion）に「プレビュー」ボタンがある。登録される項目（件名・ファイル名・課題名など）の一覧と件数を、**何も書き込まずに**表示する。
- 「同期を実行」は、先に同じプレビューを出し、「N件を『namespace』に登録します。よろしいですか？」と確認してから進む。0件のときは何もしない。
- メールは件名・差出人・日時だけを出す（本文はこの画面に出さない）。
- API: `POST /admin/sync/<gmail|calendar|drive|notion|jira|backlog>/preview`（body: `{ namespace }`）。

## 2. 連携の同期先の許可リスト

- 共有namespaceへの連携の同期・同期元の設定は、**管理者が許可リスト（`sync_allowed_namespaces`）に入れたnamespaceだけ**。管理画面「ナレッジ登録」→「同期・通知の設定」→「連携の同期先（許可リスト）」で追加・削除する（追加・削除は管理者のみ、editorは閲覧のみ）。
- リストから外すと、そのnamespaceの自動同期もすべてオフに戻る。
- 個人用namespaceは許可リストに入れられない（本人専用の接続で本人の索引にだけ書くため）。
- editorは、許可リストに入っていても、自分に許可されたnamespace（key_namespace_grants）だけに書ける。
- 導入時は、すでに同期元を設定済みの共有namespaceが自動で許可リストに入る（既存の運用が止まらないように）。
- 書き込みを伴わない手動の取り込み（URL・YouTube・ファイル・FAQ・QA・Googleマップの登録）は、この許可リストの対象外（従来どおりの権限）。

## 3. 自動同期のオプトイン

- 毎日の自動同期（Cron）は、**明示的に「毎日自動で同期する」をオンにしたnamespaceの、そのサービスだけ**。既定はオフ（`kb_sources.auto_jira` / `auto_backlog` / `auto_calendar`）。
- 同期元を解除したとき、許可リストから外したときは、自動同期もオフに戻る。
- Cronは実行のたびに許可リストを再確認し、許可の無い共有namespaceには書かない。
- Gmail・Drive・Notionには、もともと自動同期は無い（手動のみ）。

## 4. ユーザーごとの接続（自分用の連携）

- 画面右上の「自分用の連携」から、Gmail・Google Drive・Googleカレンダー・Jira・Backlog・公式MCPを**自分のアカウントで**接続できる（ゲスト以外）。
- 同期先は、自分の個人用namespace（`personal:<自分のID>`）に固定。取り込んだ内容は共有の知識ベースに入らず、他のユーザーや管理者の検索にも出ない。
- 同期のたびにプレビューで確認でき、取り込んだ内容は同じ画面の一覧から1件ずつ削除できる。
- キー（ユーザー）を削除すると、そのユーザーの接続（OAuth・公式MCP）と個人用のナレッジ・同期元の設定も一緒に消える。
- 共有の接続と本人専用の接続は、`oauth_connections` / `mcp_connections` の `owner_id`（空 = 共有、ユーザーID = 本人専用）で区別する（migrations/0021）。

### 本人専用の接続でできること・できないこと

| サービス                              | 自分用の接続 | 備考                                                                                 |
| ------------------------------------- | ------------ | ------------------------------------------------------------------------------------ |
| Gmail・Google Drive・Googleカレンダー | 可           | OAuthクライアントは共有のものを使う。承認済みリダイレクトURIは共有の接続と同じ       |
| Jira・Backlog                         | 可           | 共有のBasic認証・APIキーには**フォールバックしない**（他人の権限で動かないため）     |
| 公式MCP                               | 可           | OAuthアプリが要るサービス（GitHub・Slack・Google）は、共有と同じアプリのsecretを使う |
| Notion（同期）                        | 不可         | 共有のトークンで読むため。個人のNotionは公式MCPの「自分用」から読める                |
| Slack通知                             | 不可         | 通知はデプロイ全体のもの                                                             |

## 仕組み（実装メモ）

- `src/syncTargets.ts`: `authorizeSync`（namespaceごとの権限判定と、使う接続の持ち主の決定）、許可リストのAPI、プレビューの返し方、`startOwner`（OAuth開始で `?owner=me`）。
- `src/kbIngest.ts`: 個人用namespaceは個人用の索引（`VEC_PERSONAL`）へ、持ち主つき（`owner_user_id`）で書く。削除（`kbDocuments.ts`）も同じ索引から消す。
- `src/myConnections.ts`: `/me/connections`（自分の接続の状態と、自分用namespaceの同期元の設定）。
- OAuthの各モジュール（`jiraOAuth.ts` `backlogOAuth.ts` `calendarOAuth.ts` `googleOAuth.ts`）と `mcp/service.ts` は、接続の持ち主（`ownerId`）を引数に持つ。
- テスト（偽のGoogle/Gemini + SQLite）: 既存データを含むマイグレーション、権限判定、許可リストの操作、自動同期のオン/オフ、個人用の取り込み先（個人用の索引に入り、共有の索引に入らない）、他人からの拒否、本人専用トークンの使用、プレビューが何も書かないこと、Cronの対象、本人専用のMCP、キー削除時の掃除。実際のGoogle・Atlassianなどのアカウントでの通しは未確認。
