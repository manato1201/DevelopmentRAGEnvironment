## Slackの設定（管理者が一度だけ）

1. Slackのアプリで、スラッシュコマンド `/rag` を作り、Request URL を `https://<このWorkerのドメイン>/slack/command` にする。
2. secretを登録する。
   - `SLACK_SIGNING_SECRET` … アプリの「Signing Secret」。署名の検証に使う。**未設定だと、すべて拒否する**。
   - `SLACK_TEAM_IDS` … 利用を許可するSlackワークスペースのID（カンマ区切り）。**未設定だと、紐づけできない**。
3. 質問は、紐づいたユーザーの権限（アクセスできるnamespace・トークン予算・レート制限）で動く。ゲストは紐づけられない。
4. 答えは、Slackが発行したURL（`hooks.slack.com` など）へだけ送る。署名の時刻が5分以上ずれたリクエストは拒否する。

## 注意

- **ステージング**: 本番側を連携の許可リストに入れたままにすると、連携は本番へ直接書ける。組を登録したときに、その旨を表示する。
- **定期の再クロール**: 共有namespaceは、連携の許可リストに入っているものだけ。許可リストから外すと、そのCronは動かなくなる（スケジュール自体は残る）。
- **答えられなかった質問**: 履歴（保存期間90日）から集計する。質問文を管理者が見る機能なので、利用者への周知を推奨。
- **ストリーミング**: `/query` はこれまでどおり使える（Unityなどの既存クライアントは変更不要）。`/query/stream` はチャット画面が使う。
- テスト（偽のGemini・Slack・SQLite）: SSEの分割・思考パートの除外・失敗時の返金、署名の検証（改ざん・時刻ずれ・secret未設定）、連携コードの1回限り・期限、response_urlの検証、スレッドの他人からの隔離、プリセットの権限、ステージングの移動（ベクトルの付け替え・権限）、質問のグルーピング、スケジュールの有効化・許可リスト・再開。**実際のGemini・Slackでの通しは未確認**。
