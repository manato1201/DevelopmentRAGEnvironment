「3段階（basic/applied/advanced）で作っているが、実用にはほど遠い」という実感への対応。参考にしたのは、3つのチャンネル（Indyzone / houdini3d / Studio Satsuki）の公開情報（動画タイトル・説明欄・チャプター）です。動画の音声・映像は取得していません。

1. 何が足りなかったか（実データで確認）

既存の生成物3本（ブラックホール、APEXオートリグ、APEXリグポーズ）を、新しい採点（tutorial_review.py）にかけた結果です。

生成物 点数 手順の中身
procedural-black-hole-particles 6 / 100 create_node 5、set_parameter 6、connect_nodes 3、cook_node 2
apex-autorig-fbx-basic 6 / 100 create_node 3、set_parameter 1、cook_node 2
apex-rigpose-setdrivenkey-base 6 / 100 create_node 4、set_parameter 1、cook_node 2

3本とも、不足は同じでした。学ぶこと／考え方（用語とたとえ）／各段階の確認ポイント／パラメータ実験／仕上げ／次のレッスン／手順の「なぜ」がありません。節は「概要・手順・コード・ノード構成・ハマりポイント・応用・参考」だけで、中身は「ノードを組んだ記録」です。

注意: 手順ごとのスクリーンショット一覧は、画面が変わる操作だけを記録します。そのため、「数値での確認（inspect_geometry）」と「実験の実行」の2項目は、この一覧から数えると少なく出ます（実際より低い可能性）。残りの項目は、本文だけで判定できるので確かです。

参考チャンネルに共通する型

型 内容
「〜とは？」を先に 何で、何の役に立つかを説明してから作る
考え方 仕組み全体を、たとえで1つ
少しずつ作る 足すたびに「こう見えれば正しい」を確かめる
動かして見せる パラメータを変えて、効果を見せる
仕上げ 見た目を整える
つまずきと次回 注意点、まとめ、次回予告
シリーズ化 概要 → 各回、と段階を踏む

2. どう直したか

図: チュートリアルと動画ができるまで。トピックを入れてから、ダッシュボードに載るまでの8段階。

トピック
  └─ ① レッスン設計（lesson_design.py）  … ノードを組む前に、章立て・確認・実験を決める（Claude 1回）
       └─ ② エージェントが組む             … 設計と「教え方のルール」をシステムプロンプトに入れる
            └─ ③ finish_tutorial の品質ゲート … 抜けがあれば書き足させる（最初の2回だけ）
                 └─ ④ 採点（tutorial_review.py）… 100点満点。指標に記録
                      └─ ⑤ 動画の台本     … 考え方・確認・実験を、そのまま解説に使う
層 ファイル 内容
設計 lesson_design.py 目標・学ぶこと・用語とたとえ・章（なぜ／何を足す／何が見えれば正しいか）・実験・仕上げ・つまずき・次回。検証し、章が2つ未満なら不採用
教え方のルール 同上 TEACHING_RULES 作る順、章ごとの確認（cook + inspect_geometry）、実験は実際に値を変えて cook、確かめていないことは書かない
品質ゲート houdini_tools.py _tool_finish_tutorial 抜けた項目を名指しで返す。最初の2回だけ（予算の浪費・無限ループを避ける）
採点 tutorial_review.py 10項目。実験は、本文に書いてあるだけでなく、実際に値を変えて再 cook した回数も数える
動画 video_script.py 新しい節（学ぶこと／考え方／実験／仕上げ／次回）をスライドにし、「前→後」「ここで〇〇が見えれば正しい」と話すルールを追加
見た目の確認 houdini_tools.py _tool_confirm_tutorial confirm_tutorial の note に「見えていません」「枠のみ」などと書きながら looks_correct=true にした場合は、最大2回まで差し戻す（2026-10-21。煙のシミュレーションで、枠だけの画面のまま確定した事例への対応）。仕様で見えないときは、理由を書いてもう一度確定すれば通る

3段階の意味を変えた

名前（basic / applied / advanced）は、互換のためそのままです。意味を、難しさから1つの学習の道すじに変えました。

名前 レッスン 目的
basic 1: 「〜とは？」と最小の作り方 考え方をつかみ、3〜6ノードで最小構成を作れる
applied 2: 動かして理解する パラメータを動かして効果を体験し、見た目をコントロールする技を足す
advanced 3: 実務で使える形にする 再利用（パラメータの整理・バリエーション）と、ゲームエンジンへ渡す注意点

前のレッスンの要約は、設計にも渡します（説明済みのことは繰り返さず、一段深める）。

生成物の形（新しい節）

概要 → このレッスンで学ぶこと → 先に知っておく考え方 → 手順（各章の終わりに ✅ 確認ポイント）→ パラメータを動かして確かめよう → 仕上げ → コード・ノード構成 → ハマりポイント → 応用・発展のヒント → 次のレッスン → 参考

動画のスライドは、この順に並びます。モデルが書かなかった項目は、設計で補います。補った実験には「設計段階の予想です」と明記します（確かめていないことを、確かめたように見せないため）。

採点の10項目（合計100点）

学ぶこと 8 / 考え方 14 / 確認ポイント 16 / 実験を書いた 12 / 実験を実行した 14 / 数値で確認 8 / 仕上げ 8 / つまずき 6 / 次のレッスン 6 / 手順に「なぜ」 8。

結果は、生成の自動指標（<名前>_metrics.json）の lesson_plan・lesson_score・lesson_missing に残ります。パネルの進行表示にも「レッスン品質チェック: 78/100（不足: …）」と出ます。

3. 動画は「解説動画」になっているか

時点 判定 理由
10/18までの動画（ブラックホール 5分19秒・23スライド） なっていない 本文の朗読。元の文章が6/100の「操作の記録」
10/19の改善後（初心者向け台本・手順ごとの音声） 一歩手前 手順ごとに「何を・なぜ」を説明できる。ただし、材料が操作ログなので、考え方・確認・実験・仕上げが話せない。画面は、手順ごとの静止画1枚
今回（レッスン設計つき） 改善見込み。実機で未確認 材料に、考え方・確認・実験が入る。画面は、実験の前後が手順の画像として並ぶ

まだ解説動画として足りない点（今回は直していません）:

  • 画面が静止画中心。ビューポートの動画クリップ（viewport_clip_frames）を、実験の前後に使えば「動かして見せる」になる
  • 実験の「前→後」を、並べて見せる画面（左右比較）が無い
  • シリーズ化（概要 → 各回）の動画側の対応が無い

4. 確認できたこと・できていないこと

項目 状態
設計の検証・差し込み、採点、品質ゲート、Markdownの節の順序、動画台本の新しい節への対応 自動テストで確認（houdini/tests/test_lesson_design.py、28件）
既存の生成物の採点 確認（上の表）
Claudeが書く設計・レッスンの質 未確認（Houdini実機とClaudeの呼び出しが必要。この環境では実行していません）
品質ゲートで、モデルが実際に書き足すか 未確認。足さない場合も、設計で補うので壊れません
追加コスト 設計のClaude呼び出し1回（入力は参考文書の抜粋まで）と、品質ゲートでの再提出が最大2回。実験と確認のツール呼び出しも増える。実機でcost_usdを比べてください

5. 使い方

Houdiniのpython_panelsへ、次の2つの新しいファイルもコピーしてください（houdini_tools.pyがtutorial_review.pyを読み込むため、コピー漏れがあると生成自体が始まりません）。

lesson_design.py / tutorial_review.py / tutorial_agent.py / houdini_tools.py / video_script.py（今まで通り tutorial_view.py・video_factory_bridge.py・tutorial_feedback.py も）

生成したあと、進行表示の「レッスン品質チェック」の点数と不足項目、保存された .md の節を見てください。点数が70未満の傾向なら、lesson_missing の多い項目から、プロンプトを直します。
