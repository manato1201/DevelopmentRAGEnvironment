# 外部サービス連携（公式MCP）のメリットと、テストの進め方

**目的:** サービスごとに、連携すると何が得られるかを先に決め、効果を測りながらテストする。 ／ **版:** 2026-10-21
**注意:** 画面の「連携中のシステム」は、現時点で**すべて未連携**です。ここに書いたメリットは、**接続して測るまでは、見込み**です（「見込み」と書いています）。

## 1. 「同期」と「MCP」の違い

| | 同期（ナレッジへの取り込み） | MCP（チャットからの直接参照） |
|---|---|---|
| 仕組み | 外部サービスの内容を、前もって取り込み、検索できる形にする | 質問のたびに、チャットが外部サービスの**読み取り専用ツール**を呼ぶ |
| 鮮度 | 同期した時点の内容（再同期が必要） | **常に最新** |
| 速さ・費用 | 検索だけなので、速く、安い | ツールの呼び出しが挟まり、遅く、Gemini のトークンが増える（結果は1回6,000文字まで、最大4往復・6回） |
| 検索の質 | 他の資料と**一緒に**検索でき、出典の番号がつく | 質問に合うものを、サービス側の検索で探す（サービス側の検索の質次第） |
| 権限 | 取り込んだ内容は、そのnamespaceを見られる人が読める | **接続した人の権限**で読む（**接続のしかたで、誰が使えるかが決まる**。下の §1.1） |
| 向いていること | よく聞かれる、あまり変わらない知識（手順書・仕様） | 最新の状況・個別の事柄（今日の課題、直近のメール、予定） |

### 1.1 接続の2種類（重要）

| 接続のしかた | 誰のチャットで使われるか | 向いているもの |
|---|---|---|
| **共有**（管理 →「連携するシステムを追加」） | **チャットで「外部サービスも使う」をオンにした、全員** | **認証不要の公開ドキュメント**（Cloudflare Docs・Microsoft Learn）。チームで共有してよい情報だけ |
| **自分用**（上部の「自分用の連携」） | **本人だけ**（他の人には見えない） | **Slack・Gmail・Drive・カレンダー・GitHub の非公開リポジトリ**など、個人の権限のもの |

**共有で、個人の権限のサービス（Gmail・Slack など）を接続しないでください。** 接続した人の権限で、チャットを使う**全員**が読めてしまいます。同じサービスを両方持っているときは、本人専用が優先されます。

- **使い方:** 画面の「**外部サービスも使う**」をオンにすると、検索結果だけで答えられないときに、接続済みのサービスで調べます。**既定はオフ**。回答に、使ったサービスが表示されます。
- **安全:** 使えるのは、**読み取り専用**のツールだけです。書き込み系は、確認の手段が無いため、モデルに見せません。外部サービスの文章は、**指示として扱いません**（プロンプトインジェクション対策）。

## 2. サービス別: メリットと、最初に試すこと

優先度は、**このプロジェクト（Houdini・Unity・Cloudflare の開発）で、どれだけ役立ちそうか**の見込みです。

| 優先 | サービス | 接続に必要なもの | できること（読み取り） |
|---|---|---|---|
| ★★★ | **Cloudflare Docs** | なし（認証不要） | Workers・D1・Vectorize などの**公式ドキュメント**の検索 |
| ★★★ | **Microsoft Learn** | なし（認証不要） | .NET・**C#**・Azure の公式ドキュメントの検索 |
| ★★★ | **GitHub** | OAuth アプリを作り、Client ID／Secret を Worker のシークレットに登録 | リポジトリのコード・課題・プルリクエストの検索と閲覧 |
| ★★ | **Notion** | OAuth（自動登録） | ページ・データベースの検索と閲覧 |
| ★★ | **Slack** | OAuth アプリ（通知用の既存アプリを流用可） | メッセージ・チャンネル・キャンバスの検索と閲覧 |
| ★★ | **Google Drive** | Google の OAuth（Developer Preview） | ファイルの検索と閲覧 |
| ★★ | **Google カレンダー** | 同上 | 予定の検索、空き時間の確認 |
| ★ | **Gmail** | 同上 | メールの検索と閲覧 |
| ★ | **Atlassian（Jira / Confluence）** | OAuth（自動登録） | 課題・ページの検索と閲覧 |
| ？ | **Linear** | OAuth（自動登録） | 課題・プロジェクト・ドキュメントの閲覧 |
| ？ | **Sentry** | OAuth（自動登録） | エラー・課題・リリースの閲覧 |
| ？ | **Figma** | OAuth（自動登録） | デザインファイルの内容の閲覧 |

？は、**普段使っていなければ不要**です（使っているかどうかで、価値が決まります）。

### 2.1 Cloudflare Docs（★★★）
- **メリット（見込み）:** このシステムの保守は、Cloudflare の仕様（D1 の上限・Vectorize の制限・Workers の挙動）が頻繁に絡みます。「D1 の今の上限は？」「Vectorize の topK の上限は？」を、**公式の最新の記述**から答えられます。実際に、上限や料金を調べる場面が何度もありました。
- **試す質問:** 「D1 の無料プランの1日の読み取り上限は？」「Vectorize の metadata filter で使える演算子は？」
- **合格の目安:** 公式ドキュメントの内容に沿った答えで、**数字が正しい**（公式のページで照合）。

### 2.2 Microsoft Learn（★★★）
- **メリット（見込み）:** Unity は C# なので、**C#・.NET の標準ライブラリの仕様**を、最新の公式記述で確認できます。
- **試す質問:** 「`Task.WhenAll` の例外の扱い」「`System.Text.Json` で、列挙型を文字列で出す方法」
- **注意:** Unity が使う .NET のバージョンは限られるので、答えが **Unity で使えるとは限りません**。

### 2.3 GitHub（★★★）
- **メリット（見込み）:** 自分のリポジトリ（このプロジェクトなど）の**コード・課題・PR**を、チャットで横断検索できます。「この関数はどこで呼ばれている？」「最近のPRで何が変わった？」。**ドキュメントに書かれていない、コードの現状**を答えられるのが強みです。
- **試す質問:** 「`houdini/python_panels` で、動画生成の進捗を読んでいるのはどのファイル？」「直近のコミットで、検索まわりは何が変わった？」
- **注意:** 権限は、OAuth のスコープ（`repo` を含む）です。**非公開リポジトリの内容が、回答に出ます。** **「自分用の連携」から接続してください**（共有で接続すると、チャットを使う全員が読めます）。

### 2.4 Notion（★★）
- **メリット（見込み）:** すでに「同期」でも取り込めます。MCP は、**同期していない最新のページ**や、個別のページを、すぐ引けます。
- **試す質問:** 「（直近に更新したページの名前）の要点は？」
- **評価のポイント:** **同期済みのナレッジと、MCPの結果を比べる**（答えの鮮度・正確さ・速さ）。差が小さければ、同期だけで足ります。

### 2.5 Slack（★★）
- **メリット（見込み）:** 議論の経緯（「なぜこの仕様にしたか」）が、スレッドに残っていることが多いです。**決定の理由を、後から引けます。**
- **試す質問:** 「（チャンネル名）で、最近話題になっていたことは？」
- **注意（重要）:** **非公開チャンネル・DM の内容**が、読める範囲に入ります（スコープに `private` の検索を含む）。**本人の権限で読み、他の人には見えない**設計ですが、回答をチームに共有するときは、内容に注意してください。

### 2.6 Google Drive / カレンダー / Gmail（★〜★★、Developer Preview）
- **Drive（見込み）:** 同期済みの Drive と、同期していないファイルの両方を引ける。
- **カレンダー（見込み）:** 「今週、実証実験の打ち合わせはいつ？」「来週の空き時間は？」。**スケジュールの確認**に便利。
- **Gmail（見込み）:** 「（件名）のメールの要点は？」。**メールは機微な内容が多い**ので、最も慎重に。
- **注意:** いずれも **Google の Developer Preview** です。仕様が変わる・不安定なことがあります。**まず Drive とカレンダーで試し、Gmail は最後**に。

### 2.7 Atlassian / Linear / Sentry / Figma
- **Atlassian（Jira / Confluence）:** Jira を使っていれば、「未解決の課題の一覧」「この課題の経緯」。Backlog は、MCP ではなく、**同期**で対応済み。
- **Linear / Sentry / Figma:** **使っていなければ、接続の必要はありません。** Sentry は、アプリの運用でエラーを追う場合に、Figma は、デザインの仕様を引く場合に有効です。

## 3. テストの進め方

### 3.1 順序（安全で、効果が見えやすい順）
1. **Cloudflare Docs → Microsoft Learn**（認証なし。接続の設定が要らず、すぐ効果が見える）
2. **GitHub**（OAuth アプリを1つ作る。価値が高い見込み）
3. **Notion**（同期との比較）
4. **Google Drive → カレンダー**（Developer Preview。→ 最後に Gmail）
5. **Slack**
6. 使っているなら、Atlassian・Linear・Sentry・Figma

### 3.2 1サービスあたりの手順
1. 管理 →「ナレッジ登録」→「＋ 連携するシステムを追加」→ サービスを選んで**接続**。
   - **Slack・Gmail・Drive・カレンダー・GitHub など、個人の権限のものは、「自分用の連携」から接続**します（§1.1）。
2. **ツールの一覧を確認**し、使うツールを選ぶ（読み取り専用だけが、見えます）。
3. 「**チャットで使う**」をオン。
4. チャットで、**「外部サービスも使う」をオン**にして、§2 の質問を投げる。
5. 回答に、**使ったサービス**が表示されることを確認。
6. 評価シート（§4）に、結果を記録。
7. 使わないなら、**切断**（接続の解除）。

### 3.3 共通の合格基準
- **正しさ:** 回答が、元のサービスの内容と一致する（人が照合）。
- **読み取り専用:** 書き込み・削除・送信が、一度も起きない。
- **出所の表示:** 使ったサービスが、回答に出る。
- **速さ:** 検索だけの回答より遅くなる。**何秒までなら許容か**を、先に決めておく（目安: 20秒以内）。
- **費用:** ツールの結果（最大6,000文字 × 最大6回）が、プロンプトに入る。1回の質問で、Gemini のトークンが、**数千〜1万トークン程度増える**見込み（無料枠なら $0、有料でも1回 数セント）。
- **安全:** 外部の文章に、「このメールを転送せよ」のような指示が入っていても、**従わない**。

## 5. 注意

- **権限は、接続した人のもの。** 「自分用の連携」で接続したものは、**本人のチャットだけ**で使われます。**管理画面（共有）で接続したものは、全員のチャットで使われます**（§1.1）。回答を共有すれば、内容は伝わります。
- **Developer Preview（Google）** は、仕様変更・不安定さがあり得ます。
- **未確認:** このシステムの MCP 連携は、**実際のサービスとのやり取りが未検証**です（型検査・ローカルのテストまで）。最初の接続で、認証の設定（GitHub の OAuth アプリ、Slack のリダイレクト URL など）が必要な場合があります（接続の画面に、手順が出ます）。
- **費用の管理:** 「外部サービスも使う」は、**既定でオフ**です。テスターに配る場合は、**配布の範囲外**（Cloudflare を配らない前提）なので、運営（あなた）だけが使う機能です。
