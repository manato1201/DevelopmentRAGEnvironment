3. 「予算のトークン」と「費用」は比例しない

Worker の Claude 予算は、キャッシュを除く input_tokens + output_tokens を数えます（src/claude.ts）。しかし、チュートリアル生成は、システムプロンプトと会話履歴をキャッシュするので、費用の大半は、キャッシュの読み書きです。

生成 予算に数えるトークン 費用 費用のうち、入力・出力の直接分
pyro（設計つき） 13,062 $0.26 約 $0.11
差 約 $0.15 が、キャッシュの読み書き

そのため、配る量は「予算（トークン）」で決め、費用は実測の「1トークンあたりの費用」で換算します（現状は、約 $13〜15 / 100万トークン）。この比は、生成の長さで変わるので、上限の目安は、保守的に見ています。

4. 先確保の余裕（429 の誤作動を防ぐ）

Worker は、Claude を呼ぶ前に、max_tokens（16,000）＋ 会話の大きさ（文字数÷3 ＋ 画像1枚 1,600） を先に確保します。終盤の呼び出しでは、約 4万トークンになります。残りの予算がこれ未満だと、実際は足りていても 429 になります（呼び出しのあと、実測との差は払い戻されます）。

そのため、「10回分の実使用」に、先確保の余裕（45,000）を足して配ります。

予算 = 1回の平均 × 回数 × 余裕の倍率 + 先確保の余裕
     = 24,562 × 10 × 1.5 + 45,000 = 413,430 → 420,000（1万単位に切り上げ）

6. 再計算の方法

uv run python scripts/estimate_generation_cost.py --runs 10 --margin 1.5 --testers 10
uv run python scripts/estimate_generation_cost.py --dir C:\Users\<あなた>\Documents\RAGReelTutorial\localRAG\tutorials
  • *_metrics.json（生成）と、*_video_script.jsonのusage（台本）を読みます。レッスン設計つきの記録があれば、それだけで見積もります。
  • テスターの実測（自分の記録のほか、評価のデータに input_tokens / output_tokens / cost_usd / lesson_score が送られます）を集めて、1人あたりの実使用の分布を見てから、予算を調整してください。

7. 前提と、確認できていないこと

  • 基準の実測が少ない（設計つきの生成は1件）。
  • 台本づくりのトークンは、仮定値（8,000 入力 + 3,500 出力）。
  • レッスン設計つきの生成は、トピックによって、反復と費用が変わります（煙のシミュレーションは、確認・実験が重い側）。「3段階連続生成」は、1回で3本分を使います。
  • Gemini の契約（無料枠か有料か）は、確認できていません。
  • 公式の料金は、変わることがあります。契約前・実験前に、各社の料金ページを確認してください。
