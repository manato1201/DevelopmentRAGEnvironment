1. はじめに（全員向け）

図: システム全体の構成。手元の Houdini とパネル、Cloudflare の Worker、外部の AI・サービスの関係。

1.1 このツールは何か

自分たちの資料（Notion・Drive・Webページ・Q&Aなど）を検索して、出典つきで質問に答えるツール。質問の答えは、AIが資料を読んで作る。AIの回答は間違うことがある。必ず、出典を確認する。

1.2 使い始める

  1. 管理者から、APIキーを受け取る（長い英数字の文字列）。
  2. ブラウザで、デプロイ先のURLを開く。「APIキーを入力してください」と出る。
  3. キーを貼り付ける。使えるタブが表示される。
  • APIキーはパスワードと同じ。 他の人に見せない。チャットやメールに貼らない。
  • 失くした・漏れたかもしれないときは、すぐ管理者に連絡して、失効してもらう。
  • キーには有効期限がある場合がある。切れたら、管理者に再発行を頼む。

1.3 ロール（権限）

ロール できること 見える画面
admin（管理者） すべて すべてのタブ・管理のすべてのグループ
editor（編集者） チャット、ナレッジの登録、同期の実行と履歴の閲覧 管理 →「ガイド」「ナレッジ登録」
member（一般） チャット・グラフ・履歴・お気に入り 管理タブは出ない
guest（ゲスト） 制限つきの質問のみ。自分用の連携・Slackは使えない

画面の表示・非表示は見た目の都合で、実際の権限は、サーバー側で確認される。

1.4 画面の構成

上部に、「自分用の連携」ボタン、「テーマ」切り替え（自動／ライト／ダーク）、タブ（チャット／グラフ／履歴／お気に入り／管理）がある。

2. チャットで質問する

2.1 基本

  1. 検索対象を選ぶ（上部のチップ。§2.2）。
  2. 下の入力欄に質問を書く。Enterで送信、Shift+Enterで改行。
  3. 回答が表示される。回答の中の[1]などは、出典の番号。右側（または下）の出典パネルで、元の資料を確認できる。

答えの質を上げる質問の書き方
- 具体的に書く（「SOPとは」より「HoudiniのSOPネットワークとは何か」）。
- 知りたい対象の名前を、そのまま書く（製品名、ノード名、ファイル名）。
- 続きの質問は、同じ会話の中で行う（直近のやりとりが、文脈として渡る。§2.5）。
- 2文字以下の語だけのキーワードは、キーワード検索にかからない。意味検索で拾える長さの文にする。

2.2 検索対象（namespace）の選び方

  • チップは、検索の対象にする資料のグループ。複数を選べる。選ばないものは、検索されない。
  • 自分の個人用（personal:で始まる。自分専用）も、チップに出る。
  • 関係ない資料が混ざって、答えの質が下がるときは、対象を絞る。

プリセット（検索範囲の保存）
- 今選んでいるチップの組み合わせに名前を付けて保存できる（「保存…」）。次から、ドロップダウンでワンタッチで切り替えられる。「削除」で消す。
- 自分専用で、別の端末でも使える。
- 権限が無くなったnamespaceは、使うときに自動で外れる。

2.3 回答と出典の読み方

表示 意味
回答が少しずつ表示される ストリーミング。出典は、回答より先に出る。外部サービスのツールを使う質問は、一括で出る
出典パネルの更新 日付 その資料を登録した日
古い可能性 登録から180日以上たっている。最新の情報かを、元の資料で確認する
回答の下の引用の数 回答で、実際に引用された出典の数
引用の内訳のバー（2件以上のとき） どの出典が、どれだけ使われたか

引用が少ない・出典が無い回答は、AIが資料を使わずに答えた可能性がある。うのみにしない。

2.4 画像を添付する

入力欄のクリップのボタンで、画像（8MBまで）を付けられる。「この画像のノードは何か」のような質問に使う。画像は検索には使われず、回答を作るときだけAIに渡される。

2.5 会話（スレッド）

  • 同じ会話の中で続けて質問すると、直近のやりとり（6件・800文字まで）が文脈として渡る。
  • 話題を変えるときは、「新しい会話」を押す。これまでの会話は、履歴に残る。
  • 「会話全体をエクスポート」で、いまの会話をファイルにできる。

2.6 外部サービスも使う（出るときだけ）

管理者が、外部サービス（公式MCP）をチャットで使う設定にしているときだけ、入力欄の上に「外部サービスも使う」が出る。オンにすると、検索結果で足りないときに、接続済みのサービス（GitHub・Slack・Googleなど）の読み取り専用のツールで調べる。回答に、使ったサービスが表示される。既定は、オフ。

2.6.1 説明のレベル（おまかせ＝成長）

回答の「説明の深さ」を選べます（Web は画面上部の「説明」、Houdini パネルは Chat タブの「説明」）。

選択 説明のしかた
おまかせ（成長） これまでの質問で使った専門用語から、レベルが自動で決まります。使いこなしている用語は説明を省き、次の段階の用語を、検索結果に書かれている範囲で、1〜2個だけ紹介します
basic 専門用語は最小限。初めて出る用語には、かっこ書きで短い説明を付けます
applied 基本用語は説明せず、仕組みと理由、つまずきやすい点まで書きます
advanced 専門用語のまま、設計上の判断・代わりの方法・性能まで書きます
  • レベルの決まり方（おまかせ）: 質問に使った専門用語（SOP・VEX・PDG などの辞書）を、用語の難しさで点数にします（同じ用語は3回まで）。6点で applied、18点で advanced になります。
  • 「役に立たなかった」が直近3件続くと、一段やさしく説明します。
  • 保存するもの: 用語と回数だけです。質問の文章は保存しません。 自分の習熟度は Houdini パネルの「接続」タブで見られ、「習熟度の記録を消す」でいつでも消せます。
  • 説明の指定が無い質問は、これまでどおりです（用語の記録もしません）。
  • Houdini の チュートリアル生成も、basic / applied / advanced で説明の言葉の難しさが変わります（basic は用語を説明しながら、advanced は専門用語のまま設計判断まで）。

2.7 評価する

回答に、👍／👎を付けられる。付けた評価は、検索の改善に使われる（低評価の質問は、管理者の「回答できなかった質問」に集計される）。

2.8 背景の生き物（任意）

ヘッダーの「背景: なし」を押すと、画面の右下に、文字で描いた生き物（クラゲ）を薄く出せる。本文や操作の後ろに置かれ、クリックの邪魔にならない。もう一度押すと消える。

  • 既定は「なし」。選んだ内容は、このブラウザに覚えられる。
  • OS の「視覚効果を減らす」設定のときは、動かず、止まった絵になる。
  • 幅が 720px より狭い画面（スマホなど）では、出さない。

3. 履歴・お気に入り・グラフ

3.1 履歴

  • 履歴タブは、会話ごとの一覧。検索・名前の変更・削除・「続きから開く」ができる。
  • 質問の保存期間は90日。期間を過ぎた質問は、毎日の自動処理で消える。

3.2 お気に入り

回答のお気に入りのボタン（ピン）で、お気に入りに入れる。お気に入りタブで、まとめて見られる。

3.3 グラフ

  • 資料どうしの関係を、ネットワーク図で見る。「更新」で読み込み直し、「停止／再生」で動きを止める。
  • 表示するのは最大500件。それ以上あるときは、namespaceごとの文書数の比率に合わせて抜き出す。凡例に「表示数 / 全体」が出る。
  • ノードを選ぶと、詳細が出る。

4. 自分用の連携

上部の「自分用の連携」ボタン（guest以外）。自分専用の接続で、他の人からは見えない。

連携できるもの 取り込み先
Gmail・Google Drive・Googleカレンダー・Jira・Backlog・公式MCP（GitHubなど） 自分用の索引（personal:から始まる、自分専用のnamespace）
  • 他の人が検索しても、あなたの個人用の資料は、出ない。
  • 接続の仕方は、各サービスの「接続する」ボタン → 外部サービスの画面で許可。
  • 「取り込んだ自分用ナレッジ」で、自分の資料を確認・削除できる。
  • Slackから質問するの欄がある（§8）。

5. ナレッジを登録する（editor・admin）

管理 →「ナレッジ登録」。

5.1 ナレッジを追加する（3ステップ）

「＋ ナレッジを追加」を押すと、ポップアップが開く。

  1. 登録方法を選ぶ: ファイル／URL（YouTube・Webページ・サイト全体のクロール）／Q&A（1件、またはCSV）
  2. 内容を入れる: 登録先のnamespaceと、ファイル・URL・質問と答え。
  3. 確認して実行。
方法 注意
ファイル PDF・Word（.docx）・PowerPoint（.pptx）・テキスト・音声・動画。ファイルの種類によって上限がある（Word・PowerPointの直接アップロードは約20MB。Driveからの同期は、もっと大きくできる）
URL（1ページ） HTMLの文章を抽出して登録
YouTube 字幕・音声から文字起こし（動画のダウンロードは不要）
サイトのクロール 起点のURLから、同じサイトのリンクをたどる。階層・最大ページ数・パスの絞り込み・除外パターンを指定できる。登録するのは本文だけ（ページに<main>や<article>があればその中。ナビ・フッター・サイドバーの文字は除く）。リンクは、ナビからも集めて辿る
Q&A（CSV） questionとanswerの列が必要

クロールで、止まったとき
- 画面は、通信の失敗を最大3回まで自動で再試行する。それでも失敗したときは、登録済みの分を残して止まる。同じ操作をやり直すと、続きから再開する。
- 画面を閉じても、「中断したクロール」から「続きから再開」または「破棄」できる。
- 変わっていないページは、飛ばす（2回目以降は、速い）。短くなったページは、古い末尾も消える。

5.2 登録済みナレッジの確認・削除

「登録済みナレッジ」で、namespaceを選ぶ。検索・ページ送り・個別の削除ができる（削除は、元に戻せない。確認してから）。

5.3 namespaceごとの登録状況・重複

  • 「namespaceごとのナレッジ登録状況」: ファイル数・チャンク数・同期元・最終更新。集計は、最大10分前の値。
  • 「重複コンテンツの確認・削除」→「重複チェック」: 内容が同じ資料の組を探す。自動では消さない。不要な方を、自分で選んで削除する。

5.4 同期履歴

「同期履歴」に、日時・実行者・種別・namespace・ファイル・状態が出る。実行者は、名前、「自動（Cron）」、「不明」。実行者・状態（失敗のみ）で絞り込める。他の人の個人用namespaceの履歴は、出ない。

5.5 定期の再クロール

「定期の再クロール」で、サイトのクロールを毎日・毎週に設定できる。

  • 「有効」にしたものだけ動く（既定は無効）。
  • 変わったページだけを更新する。30分ごとに、時間の予算の範囲で、少しずつ進む。
  • 共有namespaceは、連携の許可リストに入っているものだけ（§6.3）。許可リストから外すと、動かなくなる（設定は残る）。

6. 外部サービスと連携する（editor・admin）

図: 外部サービス（MCP）の使い方と、書き込みの確認。読み取りはそのまま、書き込みは毎回「実行」を押したときだけ。

6.1 連携の基本

管理 →「ナレッジ登録」→「＋ 連携するシステムを追加」。サービスを選び、接続（OAuth）→ 同期元の設定（プロジェクトキー、カレンダーID、検索式など）→ プレビュー → 同期を実行。

サービス 同期元の設定 備考
Notion データベースID 「Notionをプレビュー」「Notion同期を実行」
Google Drive フォルダID PDF・Office・音声動画も取り込める
Jira プロジェクトキー 毎日の自動の差分同期（オンにしたときだけ）
Backlog プロジェクトキー／ID 同上
Googleカレンダー カレンダーID 固定の期間（過去7日〜未来90日）を丸ごと取得
Gmail 検索式（例 label:project-x newer_than:30d） ラベルから選べる
Googleマップ 場所の一括登録
Slack 通知の先 ヘルスチェックのアラートの通知

操作の順序（安全のため）: ①接続テスト（登録せず、設定が正しいかだけ確認）→ ②プレビュー（何が登録されるかを見る）→ ③同期を実行。失敗したものは、「失敗○○だけ再同期」。

6.2 取り込み先（namespace）への配慮

取り込んだデータは、そのnamespaceで検索される。関係のない資料が混ざると、回答の質が下がる。同期の前に、プレビューで内容を確認する。不安なときは、ステージング（§6.4）を使う。

6.3 同期先の許可リスト（admin）

「連携の同期先（許可リスト）」に載せたnamespaceにしか、連携は書き込めない。管理者が「許可する」で足す。自分用（personal:）は、本人のものだけ、自動で許可される。

6.4 ステージング（admin）

「ステージング（受け皿 → 本番）」。

  1. 「受け皿」と「本番」のnamespaceの組を登録する（受け皿は、許可リストに自動で入る）。
  2. 連携・クロールは、受け皿へ書く。
  3. 「確認する…」で、内容（抜粋・登録元・日時）を見る。
  4. 良いものを本番へ移す。要らないものは、破棄する。

注意: 本番のnamespaceを許可リストに入れたままだと、連携は、本番へ直接書ける。

6.5 自動同期

Jira・Backlog・カレンダーの毎日の自動同期は、明示的にオンにしたものだけ動く。初回の全件取り込みは、手動で1回実行する。

7. 管理者の操作（admin）

管理 →（サブタブ）。

7.1 Overview

namespace数・発行済みキー数・今月のRAG／Claudeの利用状況。

7.2 ユーザー・権限

操作 手順
APIキーを発行 「新しいAPIキーを発行」で、名前・権限（ロール）・RAGトークン上限・Claude予算・有効期限・アクセス可能なnamespaceを指定。生のキーは、この画面で一度しか見られない。コピーして、すぐ本人に渡す（60秒で隠れる）
ロールの変更・失効・削除 「発行済みキー一覧」。削除すると、そのユーザーの個人用の資料・履歴・連携の接続も消える
予算 キーごとに、RAG予算とClaude予算（チュートリアル生成など）。上限を超えると、サーバー側が止める（429）。空欄で「設定」を押すと、無制限
有効期限 キーごとに設定できる

7.3 namespace管理

namespaceの作成、参考資料数の上限（複数のnamespaceを横断検索するとき、特定のnamespaceが結果を占めすぎないようにする）、トークン予算のしきい値。

7.4 利用状況・コスト

見られるもの 使い方
回答できなかった質問（足りないナレッジ） 「出典なし」「未引用」「低評価」の質問を、同じ質問ごとにまとめて表示。「回答を登録…」で、Q&Aの追加へ進める。質問の内容を見る機能なので、利用者に周知しておく。誰の質問かは、出さない
利用状況（トークン使用量） ユーザー別のクエリ数・トークン
Claude／Gemini API使用量・コスト モデル別の呼び出し・推定コスト
監査ログ いつ・誰が・どのnamespaceを検索したか
Houdiniチュートリアルの評価 モデル・レベル・領域・タグ別の集計、CSV

7.4.1 実証実験の集計（admin のみ）

管理タブの「実証実験」で、Houdini パネルから上がった評価と利用を、1か所で見られます。管理者だけが見られます（editor・member・guest は、サブタブも API も使えません）。

表示 内容
KPI 参加者数（期間内に質問か評価があった人）、チャットの質問数、チャットとチュートリアルの好評率

  • 操作ミスは、cook エラー（7割）と自己申告（3割）を 0〜1 にそろえて合わせた値です（どちらかが欠けると、空欄）。

  • 管理者アカウント自身の利用（運営のテスト）は、数えません。

  • 参加者ごとの表には、習熟度や用語は出しません（少人数だと、個人が特定されるため）。
  • 期間は、直近7日・30日・90日・1年から選べます。
  • 説明レベルごとの評価は、説明レベルを記録しはじめた回答から集計されます（それ以前の回答は「指定なし」です）。

8. Slackから質問する

初回の設定（管理者）: Slackのアプリでスラッシュコマンド/ragを作る（Request URLはhttps://<このWorkerのドメイン>/slack/command）。secret（SLACK_SIGNING_SECRET、SLACK_TEAM_IDS）を登録する。詳細はusability-features-2026-10.md。設定されるまでは、使えない。

初回の連携（利用者）
1. Webの「自分用の連携」→「Slackから質問する」→「連携コードを発行」。
2. Slackで/rag link コード。10分以内・1回だけ使える。（APIキーをSlackに貼る必要は無い）

使う
- /rag 質問文 … 答えは、聞いた本人にだけ見える（チャンネルには出ない）。あなたの権限（見られるnamespace・予算）で動く。
- /rag unlink … 連携の解除。/rag help … 使い方。
- メンション・DM（チャット） … チャンネルで @ボット 質問 と送ると、スレッドに答えが付く（スレッドの全員に見える）。ボットへのDMは、そのまま質問できる（答えは本人だけ）。外部サービス（MCP）を使うのはDMだけで、Slackからの書き込みはできない。設定はusability-features-2026-10.mdの「チャットで答える」。キャンバスに貼る案内の下書きは、slack-canvas-guide.md。

9. Houdiniパネル

9.1 導入

配布用（実証実験のテスター）: zip を展開して、install.cmd を実行する（Houdiniのパッケージとして登録され、設定も書かれる）。手順は manual-houdini-tutorial.md §3。RAGReel（動画エンジン）は、別のインストーラー（manual-ragreel.md）。

開発者（リポジトリから、自分のHoudiniへ）:
1. uv run python houdini/deploy_panels.py 22.0 で、houdini/python_panels/のファイルを、Houdiniが読むフォルダ（Documents/houdini22.0/python_panels）へコピーする。リポジトリを直しただけでは、実機に反映されない。パネル本体（rag_chatbot.py）を直したときは、--pypanel も付ける。
2. Houdiniの Python Panel のメニューから、RAGチャットのパネルを追加する。
3. 接続タブで、接続先（Cloudflare）のURLとAPIキー、動画ギャラリー（ダッシュボード）のURLとトークンを設定する。HoudiniのPCに、Claudeの鍵を置く必要は無い。

9.3 チュートリアルを生成する

  1. Tutorialタブでトピックを入力。
  2. 生成が始まる。AIが、Houdiniの専用の場所（サンドボックス）にノードを作り、つなぎ、パラメータを設定し、cook（評価）エラーが無いかを確かめる。進行ログが出る。
  3. 完了すると、Markdownのプレビューが出る。内容を確認して、「保存」を押すと、localRAG/tutorials/に.mdと.jsonが保存される。
  4. 途中で止まるのは、反復の上限（80回）、費用の上限、予算のとき。

注意
- 生成の費用は、Claude予算から引かれる。
- 対応の範囲: SOP（モデリング）が中心。COP・LOP・VOP・CHOP・DOPも対応。KineFX／APEXは、ノード（SOPレベル）まで。apex::graphの中の編集は、できない。リグ・アニメーションの品質は、実機での検証が、まだ十分ではない。
- 生成された内容は、必ず自分で確かめる。

9.4 解説動画を作る（2026-10-19〜）

保存すると、続けて解説動画が作られる（動画の生成ファイルのパスが、接続タブに設定されているとき）。

  1. 台本づくり（数十秒）: まず、AIが初心者向けの台本を書く（導入・手順ごとの解説・つまずきやすい点・まとめ）。保存フォルダに<名前>_video_script.jsonが残る。
  2. 動画の生成（数分）: 手順ごとに音声を作り、画面の切り替えを、音声の長さに合わせる。プログレスバーに、全体の進み具合（台本 → 音声 → 描画 → 完了）が出る。進捗欄に、段階と使われた音声が出る。
  3. 説明スライドの右側は、ノードの関係図（考え方・つまずき等）か、完成画像（実験・仕上げ等）になる（空の板は出ない）。
  4. 完了すると、「動画」タブに入り、「外部プレイヤーで開く」で見られる。

音声について（2026-10-20〜）
- 何も入れなくてよい。 接続タブの URL / APIキーが入っていれば、Worker経由でGoogle Cloud の音声合成が使われる（POST /tts）。進捗欄に「音声: Google Cloud TTS:ja-JP-…」と出る。
- 1日の文字数に上限がある（鍵ごと 50,000 文字、全体 300,000 文字。日本時間で切り替わる）。5分の動画で3,000〜4,000文字。上限に達すると、その日は次の音声に切り替わる。
- クラウドの音声が使えないときは、VOICEVOX（導入済みなら自動で起動）→ Windows標準の音声（SAPI）の順に切り替わる。「従来の音声（SAPI）…」と出たら、どちらも使えていない。
- VOICEVOX（春日部つむぎ）が使われたときは、公開時に「VOICEVOX:春日部つむぎ」のクレジットを入れる。クラウドの音声では不要。

注意
- 台本の文章は、AIが書く。内容が正しいか、必ず見る。直したいときは、_video_script.jsonのnarration（読む文）・points（画面の短い文）・heading（見出し）を直して、エンジンを直接実行する（houdini-video-script.md §4）。
- AIに接続できないときは、定型の解説で台本を作る（同じ内容の繰り返しは避けるが、AIが書くものより、浅い）。
- 台本づくりも、Claude予算から引かれる。
- 台本つきの動画は、各手順の解説の長さで、時間が決まる。従来より長くなることがある。

9.5 「課題」タブ（実証実験に参加する人）

接続タブの「実証実験に参加する」を入れると、「課題」タブが出ます。流れは 図12、状態の変わり方は 図13 です。

  1. 事前アンケート（最初に1回）。学習背景・経験などを答えます。氏名など、個人を特定する情報は聞きません。
  2. 第1回〜第3回。各回に「固定課題」と「自由課題」があります。それぞれ「開始」→ 作業 →「終了して振り返りへ」→ アンケート →「送信して課題を終える」です。
    - 固定課題の題材は、Pyro・RBD・雲を、参加者ごとに順番を変えて行います。3回のうち1回だけ、「公式ドキュメント・Web検索のみ」で行います（このパネルのチャットとチュートリアル生成は使いません。使った記録は集計で確認されます）。
    - 自由課題は、自分の作りたいものを題材にします。どの回も、本システムを使って構いません。
    - 計測するのは、経過時間と、cook エラーが出たノードの数（20秒ごとに、シーンを見て数えます）です。
    - アンケートは、答えられるところだけで構いません（空欄でも送れます）。
  3. 間違えたとき
    - 振り返りの画面で「戻る」を押すと、終了が取り消され、課題が続きます。
    - 計測中に最初からやり直したいときは、「計測をやり直す」（確認のあと、その計測は破棄されます）。
    - 送信したあとでも、下の「完了した記録」の「やり直す」で取り直せます。次の回の課題を始めるまでです。破棄した記録は集計に入りません（やり直した回数は、運営に残ります）。
  4. Houdini が閉じた・落ちたとき。記録は残ります。開き直して「続きから開始」を押してください。それまでのエラーの数を引き継ぎ、閉じていた時間は作業の時間に入れません。
  5. 送信に失敗したとき。答えは残っています。ボタンが「答えを再送する」になるので、通信を確かめてから押してください。

12. 困ったとき（FAQ）

困りごと 原因と対処
「認証に失敗しました」と出る キーの貼り間違い（前後の空白）、失効、期限切れ。管理者に確認
「応答がJSONではありません…HTTP 500」 サーバー側の問題。時間をおいて再試行。続くなら管理者へ（learning/06）
回答に、出典が付かない・関係ない 検索対象を絞る。質問を具体的にする。資料が登録されていない可能性（管理者に「回答できなかった質問」を見てもらう）
新しく登録した資料が、検索に出ない 登録に失敗していないか、同期履歴の状態を見る。登録直後は、集計（ファイル数）の更新に、最大10分かかる（検索自体は、すぐ使える）
同期が途中で止まる バッチサイズを下げる（管理者）。クロールは、「中断したクロール」から再開
連携が「要再認証」になる 外部サービスの許可の期限切れ。「再認証する」を押す
429（制限を超えました） 予算の枯渇、または1分あたりの回数超過。しばらく待つか、管理者に予算を頼む
画面が崩れる ブラウザを再読み込み。直らなければ、開発者ツールのConsoleのエラーを管理者に伝える
Houdiniで修正が反映されない 実機のpython_panelsフォルダのコピーを更新したか確認
回答の内容が、間違っていた 👎を付ける。出典と元の資料で確かめる。AIの回答は、間違うことがある

問い合わせるときに伝えること: いつ・何をしたら・どう表示されたか（エラーの文言の全文）。APIキーは、貼らない。
