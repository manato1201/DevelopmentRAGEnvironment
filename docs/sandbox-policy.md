# 実行環境の隔離方針(R4)

2026-10-09 / 元: [IMPROVEMENT_PLAN_2026-10.md](../IMPROVEMENT_PLAN_2026-10.md) の R4。運用ルールは [AUTOMATION_RULES.md](AUTOMATION_RULES.md)。

## 対象と方針

| 対象 | 何が動くか | 現状の隔離 | 方針 |
|---|---|---|---|
| Houdiniチュートリアル生成 | AIがHoudiniのノードを作る・パラメータを変える | `/obj/ai_tutorial_*` のサンドボックスノード配下だけを操作。ファイル書き込み系のツールは持たない | 現状を維持。ツールを足すときも「サンドボックス外のノードを触らない」を検査に入れる |
| Houdini実機テスト | hython(GUIなし) | 手元のマシン。ライセンス・GUIの都合で隔離環境には置かない | 別扱い。テスト用の `.hip` は作業フォルダ内に限る |
| MCPクライアント(Worker) | 公式MCPサーバーのツール呼び出し | 読み取り専用ツールだけをチャットに出す。許可リスト方式。引数は監査ログに残さない | 現状を維持。書き込み系は、利用者の確認を挟む手段ができるまで出さない |
| クロール・URL取り込み | 外部のWebページを取得 | Workerの上で実行。取得先は管理者・編集者だけが指定できる | 現状を維持。ページ数の上限は無いが、状態サイズで止まる |
| ローカルRAG・スクリプト | `scripts/` のPython | 手元のマシン | 外部入力を扱うスクリプトは、作業フォルダ内に出力を限る |

## 守ること

1. 外部入力(Webページ・MCPの返り値・ユーザーのファイル)を、そのまま命令として実行しない。ツールの結果は「データ」として扱う。
2. 認証情報を、ログ・チャット・生成物に平文で出さない。
3. 破壊的な操作(削除・ロールバック・送信)は人かルールの承認を挟む([AUTOMATION_RULES.md](AUTOMATION_RULES.md))。
4. 新しい実行系(コード実行・シェル)を足すときは、サンドボックス化した実行環境から始める。
