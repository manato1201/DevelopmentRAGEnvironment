フォルダの考え方: 「誰が、何のために読むか」で分けています。使う人は guides/、実証実験を運営する人は pilot/、動かし続ける人は operations/、作り・直す人は design/ と learning/、経緯を知りたい人は reports/、言葉を引く人は reference/。

目的別の入口

こうしたい 読む資料
初めて、全体を知りたい ルートの README → プロジェクト概要 → システムガイド（図で見る）
使い方を知りたい（Houdini パネル・チャット・管理画面） ツール取扱説明書、チュートリアル生成は 取扱説明書（Houdini）
Houdini が初めて Houdini 初心者ガイド
動画生成を使いたい RAGReel 取扱説明書
Slack から質問したい RAGボットの使い方
実証実験を運営する 運営者向け手順書 → 告知・分析設計
障害が起きた・日々の点検をする 運用手順書、症状別は 保守の手順（障害記録つき）
費用・上限を知りたい 費用と利用枠
仕組みを理解して、直す・足す人になりたい 講義シリーズ（全16回） → 座学資料
設計の詳細を知りたい（Cloudflare） Cloudflare RAG 技術解説書
言葉が分からない 用語集・用語・技術解説
セキュリティ・規約を確かめる Worker の点検・ライセンス・隔離方針

この索引の保守

  • .md が元です。 .html は scripts/build_docs_html.py が作る（直接直さない）。新しい資料を HTML にするときは、そのスクリプトの DEFAULT_TARGETS に足す。
