1. Houdiniとは何か

Houdini（SideFX社）は、3DのモデリングやVFX（煙・炎・水・破壊など）、アニメーション、レンダリングを作るソフト。他の3Dソフトとの最大の違いは、手続き型（プロシージャル）であること。

他のソフトでの考え方 Houdiniでの考え方
形を、手で直接変形して作る 作り方（手順）を、ノードでつないで作る
途中を変えると、やり直しになる 手順のどこでも変えられる（変更が、後ろのノードに流れる）
完成した形が、成果物 手順そのものが、成果物（パラメータを変えれば、別の形が作れる）

プロシージャルの利点（ゲーム開発の場面で）
- 建物・地形・植生のバリエーションを、パラメータを変えるだけで量産できる。
- 「やっぱり、窓の数を増やしたい」が、最初からやり直さずに済む。
- 作った手順を、HDA（Houdini Digital Asset）にして、他のプロジェクトや、Houdini Engine経由でUnity・Unrealの中でも使える。

エディション

エディション 用途
Apprentice 無料。学習・個人の非商用
Indie 年間の収益が小さい個人・小規模向けの、低価格の商用版
Houdini FX / Core 商用の標準版

条件（収益の上限・出力の制限など）は変わる。使う前に、SideFXの公式ページで確認する。
ファイルの拡張子は、エディションで違う: .hip（FX・Core）、.hiplc（Indie）、.hipnc（Apprentice）。

2. 画面の構成

Houdiniの画面は、ペイン（区画）の集まり。ペインの組み合わせをデスクトップと呼び、用途別（Build、Animate、Technical など）が用意されている。

ペイン 役割 キー
Scene View（シーンビュー） 3Dの表示。形を見る・触る Alt+1
Network Editor（ネットワークエディタ） ノードをつなぐ場所。Houdiniの作業の中心 Alt+2
Parameters（パラメータ） 選んだノードの設定項目 Alt+3
Tree View（ツリービュー） ネットワークの階層の一覧 Alt+4
Textport（テキストポート） コマンド・Pythonの入出力 Alt+5
Animation Editor アニメーションのカーブ Alt+6
Material Palette マテリアルの一覧 Alt+7
Details View（ジオメトリスプレッドシート） ポイントなどの値を、表で見る Alt+8
Timeline（タイムライン） 画面の下。フレームの再生・移動 ↑↓←→
Shelf（シェルフ） 画面の上。よく使う道具のボタン —
  • Tab（タブメニュー）: ネットワークエディタでTabを押すと、ノードの一覧が出る。名前の一部を打つと絞り込まれる。ノードを作る基本の方法。
  • ペインは、タブで切り替えたり、分割したりできる。Parametersは、ネットワークエディタ上でPを押すと、浮かせて出せる（§10）。
  • Details View（Geometry Spreadsheet）は、最初に覚えると、理解が速い。 「いま、ポイントにどんな値が入っているか」が、数字で見える。

3. ノードとネットワーク

3.1 ノード

ノードは、1つの処理（箱を作る、動かす、色を付ける…）の部品。入力（上）から出力（下）へ、線（ワイヤ）でつなぐ。上から下へ、データが流れる。

flowchart LR A["Box<br/>箱を作る"] --> B["Transform<br/>動かす"] --> C["Color<br/>色を付ける"] --> D["OUT<br/>(Null)"]
  • つなぐ順番が、結果を決める。順番を入れ替えると、結果が変わる。
  • ノードを選ぶと、Parametersに、そのノードの設定が出る。パラメータを変えると、その下流が、自動でやり直される（cook）。

3.2 cook（クック）

ノードが、入力から出力を計算し直すこと。パラメータや入力が変わったときに、必要なノードだけが、cookされる。
- ノードが赤く表示される／警告が出るのは、cookのエラー。まず、Parametersと、ノードを右クリックして出るメッセージを読む。
- 重い処理は、cookに時間がかかる。途中の結果を保存（キャッシュ）して軽くする（§8）。

3.3 コンテキスト（ネットワークの種類）

ノードは、種類（コンテキスト）ごとの、別々のネットワークに置く。他の種類のノードは、置けない。

コンテキスト 略称 何を作るか
Object OBJ（/obj） シーンの入れ物。ジオメトリ・カメラ・ライトを置く
Geometry SOP 形（ポイント・面）を作る・加工する。最も使う
Dynamics DOP シミュレーション（剛体・流体・布など）の仕組み
VEX Operator VOP ノードをつないで、シェーダや計算を作る（VEXのノード版）
Compositing COP 画像・テクスチャの処理（21ではCopernicus）
Solaris LOP USDのシーンの組み立て・ライティング・レンダリング
Task TOP 処理の自動化・分散（PDG）。大量の処理の管理
Channel CHOP アニメーションや音の、チャンネル（時間で変わる値）の処理
Render ROP 出力（レンダリング・ファイルの書き出し）の指示

階層の例: /obj/geo1/box1 ＝ ObjectネットワークのなかのGeometryノードgeo1の、さらに中にある、SOPノードbox1。

  • Geometryノード（geo1）の中に入るには、ダブルクリック（またはEnter）。1つ上に戻るにはU。
  • よくある間違い: /objの階層に、SOPのノード（Boxなど）を置こうとする。まず、/objにGeometryノードを作り、その中に入る。

3.4 フラグ

ノードの状態を決める、小さなスイッチ。SOPでは、次の5つを、特に使う。

フラグ キー 意味 見た目
Display（表示） R このノードの結果を、ビューに出す 青い旗（右）
Render（レンダー） T レンダリングに使う結果 紫の旗
Bypass（バイパス） Q または B このノードを飛ばして、入力をそのまま通す（消さずに無効化） 黄色の旗（左）
Template（テンプレート） E ガイドとして、薄く表示する（編集の目印に使う） 栗色の旗
Lock（ロック） メニュー 結果を固定し、cookを止める 赤い旗
  • 「ビューに何も出ない」は、Displayフラグが、別のノードに立っているのが原因のことが多い。 見たいノードの、青い旗をクリックする（または選んでR）。
  • 長いネットワークの最後には、Nullノードを置き、名前をOUTにして、そこにDisplay・Renderフラグを立てるのが、定番の習慣。（途中のノードを入れ替えても、出力の場所が変わらない。他のネットワークからも、OUTを参照できる）
  • フラグは、ネットワークの種類で、少し違う（§10.7）。

4. ジオメトリの基礎（ポイント・アトリビュート）

4.1 ジオメトリの部品

部品 意味
ポイント（Point） 空間の点。位置（P）などの値を持つ
頂点（Vertex） 面が、ポイントを参照する「つなぎ目」。UVや法線を、面ごとに変えたいときに登場する
プリミティブ（Primitive） 面・曲線など、ポイントを束ねたもの（ポリゴンの面など）
ディテール（Detail） ジオメトリ全体で、1つだけの値

4.2 アトリビュート

ポイントや面に付ける、値のラベル。Houdiniは、あらゆるものを、アトリビュートで表す。

名前 意味 型
P 位置 ベクトル（x, y, z）
N 法線（面の向き） ベクトル
Cd 色（Color） ベクトル（r, g, b。0〜1）
uv テクスチャ座標 ベクトル
pscale 大きさ（コピーするときなど） 数値
id 識別番号（パーティクルなど） 整数
v 速度 ベクトル
  • Details View（Alt+8）で、いつでも値を確認できる。 ノードを選んで、Displayフラグを立てて、表を見る。
  • 自分で、好きな名前のアトリビュートも作れる（例: height）。
  • グループ: ポイントや面を、名前をつけて束ねる。「この部分だけ動かす」のような、一部への処理に使う。

4.3 座標と単位

  • 1単位 ＝ 1メートル。Yが上（Y-up）。UnityもY-upだが、Unityは左手系、Houdiniは右手系。Zの向きなどで、出力時に注意が必要。
  • スケールが合わないときは、まず、単位（メートル／センチメートル）を疑う。

5. パラメータと式

5.1 パラメータの基本

  • 数字の欄は、数字を直接入力、スライダーのドラッグ、または式を入力できる。
  • 欄の左のラベルを右クリックすると、キーフレームの設定、リセット（Revert to Defaults）などの、メニューが出る。
  • 式やキーフレームが入っている欄は、色が変わって表示される（普通の数値の欄と、見分けがつく）。色の意味は、Houdiniのバージョンや設定で違うことがある。

5.2 式（Expression）

欄に、数字の代わりに、式を書ける。

式 意味
$F 現在のフレーム番号
$FF 現在のフレーム（小数）
$T 現在の時間（秒）
$FPS 1秒あたりのフレーム数
$HIP 現在のシーンファイル（.hip）のフォルダ
$HIPNAME シーンファイルの名前
sin($T) サイン波（関数も使える）
ch("../box1/sizex") 別のノードのパラメータの値を参照
`ch("size")` 文字列の中で式を使うときは、バッククォート（`）で囲む
  • ch()による参照は、手順をつなげる最も基本の方法。 元の値を変えると、参照している値も、変わる。
  • $Fは整数。小数が必要なときは$FF。
  • 式を、数字に戻したいときは、欄を空にして入力し直す。

5.3 アニメーションの基本

  • キーフレーム: パラメータのラベルを右クリック → キーを設定。または、ビュー上でK（キーフレームを設定）。
  • フレームの移動は、タイムラインの←・→、再生は↑（逆再生は↓）。
  • カーブの調整は、Animation Editor（Alt+6）。

6. はじめての作例

目的: 「箱の表面に、球を散らす」。手順がつながる感覚を、つかむ。

  1. 画面の下部の、ネットワークエディタで、/objにいることを確認。Tab → geoと打って、Geometryを作る。ダブルクリックで中に入る。
  2. Tab → box。Boxノードができる。Displayフラグが立っていることを確認（形が見える）。
  3. Tab → scatter。BoxのOUTPUT（下の丸）から、Scatterノードの上へ、ドラッグしてつなぐ。Box表面に、点が散る。Parametersの Force Total Count を変えて、点の数を変える。
  4. Tab → sphere。Sphereノードを作る（Radiusを小さく。例 0.05）。
  5. Tab → copytopoints（Copy to Points）。1つ目の入力に、Sphere（コピーする形）、2つ目の入力に、Scatter（置き場所の点）をつなぐ。Displayフラグを、Copy to Pointsに立てる。
  6. 球が、点の位置に並ぶ。ScatterのSeedや、Box のサイズを変えて、全体が自動で変わることを確かめる。
  7. 最後にTab → null、名前をOUTにして、Copy to Pointsの後ろにつなぎ、そこにDisplay・Renderフラグを立てる。
flowchart TB Box["Box"] --> Scatter["Scatter<br/>表面に点を散らす"] Sphere["Sphere<br/>小さい球"] --> CTP["Copy to Points"] Scatter --> CTP CTP --> OUT["OUT (Null)"]

ここで学ぶこと: ①Tabでノードを作る ②上から下へつなぐ ③入力の順番に意味がある（Copy to Pointsは、1つ目が形、2つ目が位置） ④どこかを変えると、全体が自動で追従する。

7. VEXとWrangle入門

VEXは、Houdiniの、高速な計算用の小さな言語。Attribute Wrangleノードに書くと、ポイントごとに、同じ処理が実行される。

7.1 基本

Tab → attribwrangle（Attribute Wrangle）。VEXpression欄に書く。

書き方 意味
@P ポイントの位置（P）。@で、アトリビュートを読み書き
@Cd ポイントの色
@ptnum ポイントの番号（0から）
@numpt ポイントの総数
@Time 現在の時間（秒）
@Frame 現在のフレーム
;（セミコロン） 文の終わり。書き忘れるとエラー

7.2 例

// ポイントごとに、ランダムな色を付ける
@Cd = rand(@ptnum);          // rand()は、番号から、0〜1の値（色にもなる）

// 時間に合わせて、上下に波打たせる
@P.y += sin(@P.x * 2 + @Time) * 0.2;

// スライダーを作って、強さを調整する（パラメータの横の、設定ボタンから自動生成できる）
@P += @N * chf("amount");    // chf("名前") は、浮動小数のパラメータを読む
  • Run Over（何ごとに実行するか）の設定が、Pointsなら、ポイントごと。Primitives、Detail（1回だけ）もある。
  • エラーのときは、ノードに警告が出る。行番号とメッセージを読む。
  • 最初は、ノードだけで作って、慣れてから、Wrangleに置き換える方が、理解しやすい。

8. 保存・ファイル・ゲームエンジンへの出力

8.1 保存

  • シーンは、.hip（エディションによって.hiplc／.hipnc）。こまめに保存する。 自動バックアップもあるが、頼らない。
  • $HIPが、そのシーンのフォルダ。ファイルのパスは、$HIP/geo/…のように、相対的に書くと、フォルダごと移動しても壊れない。
  • シーンを開く前に、保存場所の確認。別のバージョンで保存したファイルを、古いバージョンで開けないことがある。

8.2 キャッシュ（重い処理を保存する）

  • File Cacheノードで、途中の結果を、ファイル（.bgeo.scなど）に書き出し、読み込み専用にできる。重いシミュレーションの再計算を避けられる。
  • キャッシュを読み込みに切り替えたら、上流のノードを変えても、結果が変わらないことに注意。更新するときは、書き出し直す。

8.3 ゲームエンジンへの出力

方法 内容
Houdini Engine Unity・Unrealの中で、HDAを実行。パラメータを、エンジン側から調整できる
FBX・Alembic・USD などの書き出し ROP（Render）ネットワークの、出力用ノードから書き出す
ゲーム向けのツール群 SideFXが、ゲーム開発向けのツールセット（Game Development Toolset）を公開している

手順や対応バージョンは、使う前に、SideFXの公式ドキュメントで確認する。 Houdini EngineのUnity・Unreal対応のバージョンは、Houdiniの更新に追従するまで、ずれることがある。

9. つまずきやすい点

症状 原因と対処
ビューに、何も出ない Displayフラグが、別のノードにある。見たいノードでRを押す。または、Space+H／Space+Aで、全体を表示
ノードが赤い・エラー cookエラー。ノードを選んで、メッセージを読む。つなぎ忘れ（入力が空）が、よくある原因
ノードを置けない コンテキストが違う（例: /objにSOPを置こうとした）。Geometryノードの中に入る
Tabで、目的のノードが出ない 名前が違う。英語で、一部を打つ。別のネットワークの種類では、出ない
値を変えても、変化しない その下流に、Lockや、File Cacheの読み込みがある。Bypassが立っている
形が、思った場所に出ない 単位（m／cm）、座標系（右手系／左手系）。Details ViewでPを確認
Wrangleでエラー ;の書き忘れ。アトリビュート名の綴り。型（数値とベクトルの混同）
触ってはいけないものを触った Ctrl+Z（元に戻す）。メニューのEditで確認
昨日の自分の作業が分からない ノードに名前を付ける。Sticky Note（Shift+P）や、Network Box（Shift+O）で、まとめて説明を書く

10.7 フラグのキー（ネットワークエディタ）

Q・W・E・R・Tが、フラグのキー。ノードを選んで押すと、切り替わる。押し続けて、ノードをクリックすると、複数を、まとめて設定・解除できる。QとBは、常にBypass。公式の説明では、Rが最もよく使うフラグ、次にE、T、Wの順。

ネットワークの種類で、フラグの意味が違う（公式のNode flagsより）。

ネットワーク Q／B W E R T
Object（/obj） — — Selectable（ビューで選べる） Display（ビューに出す） —
SOP（ジオメトリ） Bypass Selectable Template Template Display Render
DOP（ダイナミクス） Bypass — Hidden（隠す） Output（シミュレーションの出力） —
COP（Copernicus） Bypass Shaded Template Template Display 3D Output
ROP（レンダー） Bypass — — — Render（レンダー実行のボタン）
VOP Bypass — — Debug —
CHOP Bypass — Export Display Output
TOP（タスク） Bypass — — — Output

表の「—」は、公式のページに、そのキーの記載が無いもの。Lock・Unload・Materialなどは、キーが無く、ノードを右クリック → Flagsのメニューで設定する。

10.8 キーを自分で確認・変更する

  • メニューの Edit → Hotkeys で、すべての割り当てを、確認・変更できる。
  • Ctrl + Alt + Shift を押しながら、画面上のボタンやメニューをLMBクリックすると、そのボタンに対応するキーの設定画面が開く。
  • 保存・元に戻す・コピーなど、一般的な操作（Ctrl+S・Ctrl+Zなど）は、公式の一覧ページには載っていない。Editメニュー・Fileメニューに、割り当てが表示されるので、そこで確認する。

12. このプロジェクトとの関係

このリポジトリには、HoudiniのパネルからRAGに質問し、チュートリアルを自動生成する仕組みがある。この資料の知識は、その使い方に直結する。

この資料の知識 プロジェクトでの使いどころ
ノード・ネットワーク・コンテキスト（§3） 生成されるチュートリアルは、どのネットワーク（SOP・COPなど）で作るかを、決めて始まる。読むときは、/obj/geo1/…の階層から追う
フラグ・cook（§3.2・§3.4） 生成の合格条件の1つが、cookエラーが無いこと。ノードが赤いときは、cookエラー
パラメータと式（§5） 生成ツールのset_parameterは、値・式・キーフレーム・ランプを設定する
アトリビュート（§4） 生成された手順の、Cd・P・Nなどの扱いを読み解く
ショートカット（§10） チュートリアルを、実際に手で追いながら確かめるとき
  • 生成の対応範囲（SOP中心、KineFX／APEXはSOPレベルまで）は、user-manual.md §9と、learning/03-specialized.md §7を参照。
  • 生成された手順は、必ず、自分の手で追って確かめる。AIの生成物は、間違うことがある。
