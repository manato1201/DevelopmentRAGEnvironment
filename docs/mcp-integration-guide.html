1. 「同期」と「MCP」の違い

同期（ナレッジへの取り込み） MCP（チャットからの直接参照・操作）
仕組み 外部サービスの内容を、前もって取り込み、検索できる形にする 質問のたびに、チャットが外部サービスのツールを呼ぶ
鮮度 同期した時点の内容（再同期が必要） 常に最新
速さ・費用 検索だけなので、速く、安い ツールの呼び出しが挟まり、遅く、Gemini のトークンが増える（結果は1回6,000文字まで、最大4往復・6回）
検索の質 他の資料と一緒に検索でき、出典の番号がつく サービス側の検索の質次第
権限 取り込んだ内容は、そのnamespaceを見られる人が読める 接続した人の権限で動く（誰が使えるかは、§2）
できること 読むだけ 読む＋（許可したものは）書く・作る・送る
向いていること よく聞かれる、あまり変わらない知識（手順書・仕様） 最新の状況・個別の事柄（今日の課題、直近のメール、デプロイの状態）と、操作

2. 接続の2種類と、書き込みの安全装置

図: 外部サービス（MCP）の使い方と、書き込みの確認。読み取りはそのまま、書き込みは毎回「実行」を押したときだけ。

2.1 誰の権限で動くか

接続のしかた 誰のチャットで使われるか 読む 書く
共有（管理 →「連携するシステムを追加」） チャットで「外部サービスも使う」をオンにした、全員 できる できない（誰の権限で書くのか分からなくなるため、常に読み取りのみ）
自分用（上部の「自分用の連携」） 本人だけ できる 許可したツールだけ、毎回の確認つきで

共有で、個人の権限のサービス（Gmail・Slack・GitHub など）を接続しないでください。 接続した人の権限で、チャットを使う全員が読めてしまいます。共有に向くのは、認証が要らない公開ドキュメント（Cloudflare Docs）だけです。

2.2 書き込みは、3つの条件がそろったときだけ（2026-10-22 追加）

別プロジェクト（AxChatD）の「実行前の承認」の考え方を取り入れました。

  1. 本人専用の接続であること（共有の接続では書かない）。
  2. ツールの選択で、そのツールに明示的にチェックを入れたこと。初期状態は、読み取りのツールだけです（書き込みのツールは、チェックなしで表示されます。保存の操作で、うっかり有効にならないようにしています）。
  3. 実行の前に、毎回、確認画面で「実行」を押すこと。

流れ:

質問「Vercel の最新のデプロイを、再デプロイして」
  → モデルが書き込みツールを呼ぼうとする（この時点では、何も実行されない）
  → 回答の下に、確認カード（ツール名と、引数の内容。「実行」「やめる」）
  → 「実行」を押す → サーバーが、保存してある内容を、1回だけ実行する
  • 確認は1回だけ有効・5分で失効・本人だけが使えます。
  • 実行されるのは、サーバーに保存した内容です。画面から別の引数を送っても、使われません（見せた内容と、実行する内容が、必ず一致します）。
  • 実行したあとで、管理者がツールを無効にしていた・接続を共有に変えていた場合は、実行されません。
  • 1回の回答で出せる確認は、3件までです。
  • 実行の記録は、監査ログ（mcp_audit）に残ります（引数の中身は、記録しません）。
  • 外部サービスの文章は、指示として扱いません（プロンプトインジェクション対策）。

おすすめの始め方: まず、読み取りだけで試します。書き込みは、取り消せる操作（ドラフトの作成、コメント）から、1つずつ許可してください。削除・送信・公開・デプロイのような、取り消せない操作は、最後に。

3. 目的別の選定

「企画書作成・UI作成・曲作成・DCCツール・ゲームエンジン・バージョン管理・連絡ツール・配信サービス」を、どこで・何でつなげるかを整理しました。

大事な前提: このチャットは Cloudflare の Worker（インターネット上）で動きます。つなげられるのは、インターネットから届く、公式の MCP サーバーだけです。自分のPCの中で動く MCP（Blender・Unity・Houdini・Docker など）は、Worker からは届きません。それらは、手元の Claude（Claude Code / デスクトップ）で、直接つなぎます（すでに Blender は、デスクトップの Claude につながっています）。

分野 このチャット（Worker）でつなぐ 手元の Claude でつなぐ（ローカル） 見送り・できないこと
企画書作成 Notion・Google Drive（Docs）・Canva（スライド・企画書の書き出し） — —
UI作成 Figma・Canva — —
曲作成 — — 公式のリモート MCP が見つかりませんでした（曲データの閲覧サービスはあるが、作曲・生成ではない）。見つかったら追加できます
DCC ツール — Blender（接続済み）・Houdini（hython・パネル） ローカルのツールなので、Worker からは操作できません
ゲームエンジン — Unity（uloop のスキル） エンジン自体は、ローカル
バージョン管理 GitHub git（Claude Code） —
連絡ツール Slack・Gmail・Google カレンダー — Discord は、公式のリモート MCP が見つかりませんでした
配信サービス Vercel（デプロイの確認・ログ）・Cloudflare Docs wrangler（Claude Code） YouTube・Twitch の公式の MCP は、見つかりませんでした
コンテナ（Docker） — Docker の MCP Toolkit（ローカル） 公式のリモート MCP が存在しません（Docker は、自分のPCで動くため）。Worker からは操作できません

3.2 外したもの（使わないため）

Linear・Sentry・Atlassian（Jira / Confluence の MCP）・Microsoft Learn を外しました（選定した10サービスに絞る）。普段使っていないサービスを残すと、選択肢が増えて、見づらく、誤って接続するもとになるためです。
- Jira・Backlog の課題の同期は、MCP とは別の機能なので、そのまま残っています（「同期」の欄）。
- 必要になったら、src/mcp/providers.ts に、公式の URL を1件足すだけで、戻せます。

3.3 追加の候補（今は入れていません）

候補 何ができるか 入れていない理由
Cloudflare（Observability・Builds・Bindings） Worker のログ・ビルドの確認 ほしいときに足せます（自動登録に対応。書き込みの範囲が広いので、読み取りの範囲から）
Riverside 動画・ポッドキャストの編集・公開 配信の用途が決まってから
Adobe Adobe の制作ツール 利用の有無が不明
Supabase・Stripe・Hugging Face・Dropbox それぞれのサービスの操作 用途が無いため
Render デプロイ 自動登録に非対応（OAuth アプリが必要）。Vercel を使うなら不要

4. 確認できていないこと（接続の画面で確かめてください）

  • Vercel・Canva・Figma は、自動登録（DCR）の窓口が公開されています。ただし、どのアプリでも登録を受け付けるか（許可されたクライアントだけか）は、実際に接続するまで分かりません。接続でエラーになったら、メッセージを教えてください。
  • Google 系（Drive・カレンダー・Gmail）: 「redirect_uri_mismatch」と出たら、Google Cloud の OAuth クライアントに、次の URL を完全一致で追加します。
    https://rag-poc.manato1201m.workers.dev/admin/oauth/mcp/callback
  • 書き込みの確認の動作は、偽のサーバーでテストしました。実際のサービスでは、まだ試していません。

5. テストの進め方

5.1 順序（安全で、効果が見えやすい順）

  1. Cloudflare Docs（認証なし。すぐ効果が見える）
  2. Notion（自分用で接続）→ GitHub
  3. Canva・Figma・Vercel（読み取りから）
  4. Google Drive → カレンダー（Developer Preview）→ 最後に Gmail
  5. Slack
  6. 書き込みの許可は、最後に、1つずつ

5.2 1サービスあたりの手順

  1. 管理 →「ナレッジ登録」→「＋ 連携するシステムを追加」→ サービスを選んで接続。
    - Slack・Gmail・Drive・カレンダー・GitHub・Notion・Canva・Vercel など、個人の権限のものは、「自分用の連携」から接続します。
  2. ツールの一覧を確認し、使うツールを選ぶ（書き込みは、チェックなしで表示されます）。
  3. 「チャットで使う」をオン。
  4. チャットで、「外部サービスも使う」をオンにして、質問する（回答に、使ったサービスが出ます）。
  5. 書き込みを許可したときは、確認カードの内容（引数）が、頼んだ内容と合っているかを見てから、「実行」を押す。
  6. 評価シート（§6）に、結果を記録。
  7. 使わないなら、切断。

5.3 試す質問の例

サービス 質問
Cloudflare Docs 「D1 の無料プランの1日の読み取り上限は？」
GitHub 「houdini/python_panels で、動画生成の進捗を読んでいるのはどのファイル？」
Notion 「（直近に更新したページの名前）の要点は？」
Vercel 「（プロジェクト名）の、最新のデプロイの状態と、失敗しているログは？」
Canva 「最近のデザインを一覧にして」
カレンダー 「来週の空き時間は？」

5.4 共通の合格基準

  • 正しさ: 回答が、元のサービスの内容と一致する（人が照合）。
  • 書き込み: 確認カードが出る前に、実行されない。「やめる」で、何も起きない。確認の内容が、頼んだ内容と一致する。
  • 出所の表示: 使ったサービスが、回答に出る。
  • 速さ: 検索だけの回答より遅くなる。何秒までなら許容かを、先に決めておく（目安: 20秒以内）。
  • 費用: ツールの結果（最大6,000文字 × 最大6回）が、プロンプトに入る。1回の質問で、Gemini のトークンが、数千〜1万トークン程度増える見込み。
  • 安全: 外部の文章に、「このメールを転送せよ」のような指示が入っていても、従わない。

7. 注意

  • 権限は、接続した人のもの。 自分用の接続は、本人のチャットだけで使われます。共有の接続は、全員のチャットで使われます（読み取りのみ）。
  • Developer Preview（Google） は、仕様変更・不安定さがあり得ます。
  • トークンは、D1 に保存されます（暗号化は、未実装）。管理画面から、いつでも切断できます。
  • 費用の管理: 「外部サービスも使う」は、既定でオフです。配るテスターには、使わせない前提です（運営だけが使う機能）。
  • 別プロジェクト（AxChatD）との違い: あちらは、タグ（Web に埋め込む匿名の訪問者向け）の許可リストや、API キー方式（Google マップ）、アカウント名の表示も持ちます。この環境には、入れていません（必要になったら取り入れられます）。
