## 1. 目的・仮説

**目的:** houdini21が自動生成するチュートリアル（Markdown＋ノードグラフJSON）が、Houdini初心者の学習に対して、既存の（人間が書いた）チュートリアルと比べて何らかの差（効果・効率・満足度）を生むかを検証する。

**仮説（検証対象）:**

| 仮説ID | 内容 |
|---|---|
| H1 | AI生成チュートリアルで学んだ参加者は、既存チュートリアルで学んだ参加者と比べて、再現タスクの完了率・所要時間に差がある |
| H2 | AI生成チュートリアルで学んだ参加者は、ノードの「意味」を説明する理解度クイズの点数が既存チュートリアルの参加者と異なる |
| H3 | AI生成チュートリアルは既存チュートリアルと比べて、わかりやすさ・自己効力感（自分でもできそうという感覚）の自己評価が異なる |

**測定しないこと（誤解防止）:** 「Houdiniそのものが学べるか」ではなく「チュートリアルの生成手段（AI生成 vs 人手）が学習成果に与える差」を測る。チュートリアルなし条件は置かない（対照群あり・両群ともチュートリアルを使う設計を選択済み）。

---

## 2. 対象者の条件

**適格基準（Inclusion）:**
- Houdiniの使用経験が概ね6か月未満、またはノードベースのプロシージャルツール（Houdini/Blenderジオメトリノード等）を体系的に使ったことがない
- ノードグラフ・パラメータ設定の概念（GUIでの数値入力操作程度）は理解できる（完全な未経験者すぎると測定がプログラミング理解度に寄ってしまう）
- 実験用のHoudini環境（後述）を1回、30〜60分程度使える

**除外基準（Exclusion）:**
- Houdiniで3Dモデリング/VFX業務経験がある、または大学等でHoudiniの授業を1コマ以上受けたことがある（天井効果を避けるため）
- 今回検証する2トピック（§4）について既に見聞きした・チュートリアルを見たことがある

**人数の目安:**
- 各群 最低8〜10名（合計16〜20名）を目標にする。外部公表するなら、この人数では「統計的に有意」とは言えないため、レポートでは「傾向」「探索的結果」として扱う前提で計画する（§9参照）
- 学生対象なら、1〜2コマの授業やゼミの受講者から募集するのが現実的

**募集方法（要判断）:** 学内掲示・SNS募集・知人紹介など、実施主体側で決める必要がある（§11）

## 3. テスト設計（対照群比較）

**割り付け:** 参加者をランダムに2群に分ける（乱数または名簿シャッフルでよい。参加者自身が群を選べないようにする）。

| 群 | 学習手段 |
|---|---|
| **A群（実験群）** | houdini21が自動生成したチュートリアル（Markdown＋ノードグラフJSON、Houdiniパネルで実際に再生・確認） |
| **B群（対照群）** | 同じトピックの、人間が書いた既存チュートリアル（公式ドキュメント or 定評のあるコミュニティチュートリアルから選定） |

**設計方針:** Between-subject（参加者ごとに1群のみ）を採用する。Within-subject（両方体験）は「AI生成の効果」と「2回目だから慣れて上手くなった」が混同するため今回は避ける。

**トピックは両群で完全に同一のものを使う。** チュートリアルの「作り手」だけが変数になるようにする（§4で詳述）。

## 4. テスト内容の共通化

すべての参加者が同じ条件で臨めるよう、以下を固定する。

| 項目 | 固定内容 |
|---|---|
| **トピック** | 難易度の異なる2トピックを選定し、全参加者が両方とも学ぶ（例: ①グリッドに岩をランダム散布する基本セットアップ、②地形にノイズで凹凸をつけるセットアップ）。両トピックとも houdini21 の完成条件（3〜8ノード程度）の範囲内 |
| **チュートリアル分量** | A群・B群で「ノード数」「手順の文字数」がおおむね同等になるようトピック・素材を事前選定する（B群の既存チュートリアルが極端に長い/短い場合は別トピックを検討） |
| **学習時間** | 各トピックにつき最大20分の上限を設定し、両群同一にする（時間内に終わらなければ「未完了」として記録する。無制限にすると個人差が測定を圧倒する） |
| **環境** | 同一バージョンのHoudini・同一スペックのPC（実験用に統一した端末を用意するか、参加者の自宅PCでもHoudiniバージョンだけは揃える） |
| **進行手順（スクリプト化）** | 実施者が全参加者に同じ説明文を読む/配布する。「わからないことがあっても実施者は教えない」「チュートリアル以外の外部検索は禁止」等のルールを事前に明文化し、全員に同じ形で伝える |
| **実施者の中立性** | A群かB群かで実施者の態度・ヒント量が変わらないようにする。可能なら実施者自身にも参加者がどちらの群か伏せる（簡易ブラインド） |

## 5. 測定方法・指標

トピックごとに以下を実施する（事前テストは初回のみで良い）。

| タイミング | 測定内容 | 指標化 |
|---|---|---|
| **事前** | Houdini基礎知識の簡易チェック（5問程度）／自己効力感アンケート（「ノードベースツールをどの程度使いこなせると思うか」等、5段階） | 事前スコア（ベースライン） |
| **学習直後** | ① 再現タスク: チュートリアルを閉じ、白紙の状態で同じセットアップを自力で再構築する（時間計測・完了判定） | 完了率／所要時間 |
| | ② 理解度クイズ: 各ノードが「何をしているか」を自分の言葉で説明させる（3〜4問、模写ではなく理解を問う） | 採点（ルーブリック化して2名以上で採点し一致率を確認） |
| | ③ 自己効力感アンケート（事前と同一項目） | 事前比の変化量 |
| **後日（可能なら1週間後）** | 再現タスクの再実施（保持テスト） | 忘却の程度（完了率の変化） |

**ルーブリック（理解度クイズの採点基準）は両群共通で事前に作成し、採点者はどちらの群の回答か分からない状態（ブラインド）で採点する。** これがないと「AI生成だから甘く/厳しく採点してしまう」バイアスが入る。

## 6. 意見収集の条件

| 項目 | 内容 |
|---|---|
| **実施タイミング** | 各トピック終了直後に短いアンケート（5分程度）。両トピック終了後に総合アンケート（10分程度） |
| **形式** | 5段階Likert（わかりやすさ・情報量・信頼度・もう一度使いたいか等）＋自由記述（良かった点・困った点） |
| **A群限定の追加質問** | 「AIが生成したと感じたか」「不自然/不正確に感じた箇所はあったか」「cookエラーに遭遇したか」 |
| **匿名性** | アンケートは参加者IDのみで紐付け、氏名は別管理（§7） |
| **回収方法** | Googleフォーム等で回収し、自由記述に個人情報が入らないよう事前に注意書きを入れる |

## 7. 倫理・データ取扱い

外部向け（発表・対外公表・学生対象）のため、社内限定パイロットより厳格に扱う。

- **説明文書・同意書:** 研究目的、参加は任意でいつでも撤回可能なこと、データの使途（発表・論文等に匿名化した形で使用する可能性）、保存期間、問い合わせ先を明記した文書を用意し、参加前に署名（または電子的な同意）を得る
- **倫理審査:** 学生を対象にする場合、所属機関に人を対象とした研究の倫理審査（IRB相当）の制度があるか確認し、必要なら事前申請する（§11 未確定事項）
- **匿名化:** 発表・公表時は参加者ID（P01, P02...）のみを用い、氏名・学籍番号・所属等の識別情報は含めない。年齢層・経験レベル等の属性は集計値のみ開示する
- **データ保存:** 生データ（同意書・氏名と参加者IDの対応表）とアンケート回答は別々に保管し、アクセスできる人を限定する。保存期間を定め、期間終了後は削除する
- **未成年者:** 学生が未成年の場合は保護者の同意が別途必要になる可能性がある（§11）
- **撤回権:** 参加者はテスト後でもデータの削除を申し出られることを明示する

## 8. 実施手順・スケジュール

```
① 参加者募集・適格性確認（§2の基準でスクリーニング）
② 同意取得（説明文書の説明＋署名）
③ 群のランダム割り付け（実施者が記録、参加者には明示しない）
④ 事前テスト（Houdini基礎チェック＋自己効力感アンケート）
⑤ トピック①学習（A群 or B群の指定チュートリアル、最大20分）
⑥ トピック①測定（再現タスク・理解度クイズ・アンケート）
⑦ トピック②学習（同上）
⑧ トピック②測定（同上）
⑨ 総合アンケート
⑩（1週間後）保持テストの再実施（可能な範囲で）
```

1人あたり所要時間の目安: 初回セッション 60〜90分、保持テスト 15〜20分。

## 9. 分析方法

- **人数が少ない（各群8〜10名程度）ことを前提に、統計的検定より記述統計＋傾向の可視化を主とする。** 平均・分散・個人差の散布図で群間差を示し、「傾向として差が見られた／見られなかった」という記述にとどめ、「統計的に有意」という表現は使わない（サンプルサイズ的に誤解を招くため）
- 参考として群間差の検定（t検定やMann-Whitney U検定等）を補助的に実施してもよいが、結果の主軸にはしない
- 自由記述はテーマごとに分類（例:「わかりやすさ」「AIらしさへの言及」「エラーに関する言及」）し、頻度と代表的なコメントを提示する
- 理解度クイズの採点者間一致率（Cohen's κ等）を報告し、採点基準の信頼性を示す

## 10. 既知の限界・バイアスリスク

| リスク | 内容 | 緩和策 |
|---|---|---|
| サンプルサイズ | 外部公表するには小規模。一般化は困難 | レポートで「探索的パイロット」と明記し、過度な一般化をしない |
| トピック選定バイアス | houdini21が得意なトピックだけを選ぶと結果が偏る | トピック選定の理由を事前に記録し、選定基準（完成条件の範囲内・既存チュートリアルが存在すること）を公開する |
| 対照群チュートリアルの質のばらつき | 既存チュートリアルの巧拙で結果が変わる | 事前に複数の候補から「分量・難易度が同等」なものを選び、選定理由を記録する |
| 採点者バイアス | 理解度クイズの採点で群がわかると印象が採点に影響する | 採点時は群を伏せる（ブラインド採点） |
| 実施者バイアス | 実施者の態度がA/Bで変わる | 進行スクリプトを固定し、可能なら実施者も群を伏せる |
| 学習の転移 | トピック①の経験がトピック②に影響する | トピックの順序を参加者間でランダムに入れ替える（カウンターバランス） |

## 11. 未確定事項（要判断）

以下はこちらでは決められないため、実施前に確認・決定してください。

1. **募集方法・母集団:** 学生を具体的にどこから募集するか（授業・ゼミ・SNS等）
2. **倫理審査の要否:** 所属機関・発表先（学会・社内発表等）に応じた倫理審査手続きが必要かどうか
3. **未成年者の扱い:** 学生に未成年が含まれる可能性があるか、保護者同意が必要か
4. **対照群の既存チュートリアルの具体的な選定:** どの公式/コミュニティチュートリアルを使うか（トピック確定後に選ぶ）
5. **謝礼・インセンティブの有無**
6. **発表先・公表範囲:** 学会発表か、社内資料か、ブログか（同意書の文言に直結する）
