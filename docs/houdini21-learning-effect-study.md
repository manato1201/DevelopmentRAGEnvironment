## 2. 対象者・適格基準

課題シートの定義をそのまま適格基準（Inclusion）とする。

**適格基準（Inclusion、すべて満たすこと）:**
- Houdini使用経験1年以上
- デジタル造形を履修し評定B以上
- モデリング・リギング・マテリアル・アニメーション・UV展開を自力で実施できる
- 東京校または名古屋校のCGコース学生

**除外基準（Exclusion、追加提案）:**
- 本システム（RAG+MCPチュートリアル生成システム）を実験より前に使用した経験がある学生（B群での「システムへの慣れ」がA群と比較不能な交絡要因になるため）
- 実験で使用するタスクの元ネタ（対象ノード・機能のバージョン変化）について、既に社内資料・SNS等で見聞きしている学生（天井効果の回避）

**募集人数の目安:** [§6](#6-サンプルサイズ検出力の目安)参照。両校合わせて各群12〜15名（合計24〜30名）を目標とし、下回る場合は結果を「探索的所見」として扱う前提を明記する。

## 3. 群割り当て：均等化の具体的手順

課題シートの「事前アンケートで学習背景・技術的背景・実務経験を確認し、ABグループのレベルが均等になるよう割り振る」を、実施可能な手順に分解する。**完全ランダム割り当て＋事後検証**ではなく、**層化ブロックランダム化**を第一候補とする（小サンプルでは完全ランダムだと群間差が偶然生じるリスクが相対的に高いため）。

### 3.1 層化に使う変数

事前アンケートの回答から、以下2軸で層を作る（軸を増やすとセルが空になりやすいため2軸に絞る）。

| 軸 | 区分 |
|---|---|
| Houdini使用経験年数 | 1〜2年 ／ 3年以上 |
| 実務経験（インターン・アルバイト等でのHoudini使用歴） | あり ／ なし |

→ 2×2＝4層（例：①1〜2年×実務なし、②1〜2年×実務あり、③3年以上×実務なし、④3年以上×実務あり）

### 3.2 割り当て手順

1. 事前アンケート回収後、参加者を上記4層に分類する。
2. 各層内で参加者をランダムな順序に並べ、2人1組のブロックを作る（層内の人数が奇数の場合は最後の1人を乱数でA/Bのどちらかに割り当てる）。
3. 各ブロック内で乱数（コイントス相当、`random.choice`等）によりA/Bを1人ずつ割り当てる。これにより層ごとの人数がA/Bでほぼ一致する。
4. 校舎（東京校／名古屋校）は層化の3軸目にはせず、割り当て後に**確認変数**として記録する（実施場所の違いは[§4.4](#44-実施環境の統制)で別途統制）。

### 3.3 割り当て後の検証（レポートに必須で記載）

割り当てが終わったら、以下を**必ず**検定し、群間の均等性を報告書に明記する（層化しても偶然の偏りが残る可能性があるため、割り当てて終わりにしない）。

| 比較対象 | 尺度 | 検定 |
|---|---|---|
| 使用経験年数 | 連続量（年数） | Mann-Whitney U検定 |
| 実務経験の有無 | 二値 | Fisherの正確検定 |
| デジタル造形の評定 | 順序尺度 | Mann-Whitney U検定 |
| 自己評価スキルレベル（事前アンケートに5段階等で追加する場合） | 順序尺度 | Mann-Whitney U検定 |

すべてp>0.10程度であれば「群間に有意な背景差はない」と報告できる状態。もし有意差が出た場合は、その変数を後述の統計解析（[§7](#7-統計解析計画)）で共変量として補足するか、論文の限界として明記する。

## 4. 実験の共通項目（交絡変数の統制）

A群・B群で**タスクそのものの難易度・環境・進行が完全に同一**であることを保証するための項目。「システムを使うかどうか」以外の変数を極力揃える。

### 4.1 タスク内容・難易度

| 項目 | 統制方法 |
|---|---|
| タスクの選定 | バージョン変化で手順が変わったHoudiniの操作を1〜2個選定し、両群に**完全に同一のタスク文（課題文）**を与える。A群向け・B群向けで文言を変えない（システム利用の許可/禁止のルールのみ別紙で伝える） |
| 事前パイロット | 実験対象外の学生2〜3名（対象者条件を満たす）でパイロットを実施し、時間内に完了可能な難易度か、指示文に曖昧さがないかを確認してから本実験に入る |
| 複数タスクがある場合の順序 | タスクが2つ以上ある場合は提示順序を参加者間でランダムに入れ替える（カウンターバランス）。学習の転移（1つ目の経験が2つ目に影響）を両群で均等にする |
| 完成条件の明示 | 「ここまで出来たら完了」という完成条件（ノード構成・見た目・パラメータ値など）を両群に同一の基準で事前提示する。採点者の主観が入らないようにする |

### 4.2 時間制限

- 両群同一の上限時間を設定する（例：60分。パイロット結果を踏まえて調整）。
- 時間内に完了しなかった場合は「未完了」として記録し、そこまでの進行度を[§5.1](#51-客観指標)の代替指標として残す（完了率も比較対象にできるようにする）。
- 時間無制限にすると個人差（作業速度そのもの）が学習効果の差を圧倒してしまうため、上限は必須。

### 4.3 実験者の説明の仕方

- 進行スクリプトを文書化し、全参加者に**同じ文言**を読み上げる／配布する。アドリブでの説明を禁止する。
- スクリプトに含める内容：実験の目的（詳細は伏せてよいが同意書の範囲で）、タスク文の説明、時間制限、使用可否のルール、質問への対応方針（下記）。
- 実験者が松浦氏本人（システム開発者）である場合、B群の参加者に対して無意識に期待的な言動（Hawthorne効果・実験者効果）が出やすいため、進行スクリプトの読み上げは録音済み音声やテキスト配布で代替し、対面での温度差が出ないようにすることを推奨する。

### 4.4 実施環境の統制

| 項目 | 統制方法 |
|---|---|
| PC・スペック | 同一スペック・同一Houdiniバージョンの端末を使用する（学校のPC教室の同型機を優先。私物PCが混在する場合はHoudiniバージョンだけは必ず揃える） |
| 実施場所 | 東京校・名古屋校で実施する場合、両校でA群・B群が両方発生するように振り分ける（片方の校舎がすべてA群、もう片方がすべてB群、という割り当てはしない。校舎差が群間差と交絡してしまう） |
| 実施日時 | 両群の実施を同一期間（1〜2週間以内）に収め、期間中にHoudiniのマイナーアップデートやシステム側の仕様変更が入らないようにする。午前/午後などの時間帯も両群に分散させる |
| ネットワーク環境 | A群のWeb検索・B群のRAGサーバー通信のいずれも、同程度の回線速度の環境で実施する（極端に遅い回線での実施を避ける） |

### 4.5 群間の情報漏洩の防止

- A群の参加者に本システムの存在・使い方を実験前に知らせない（B群経由で情報が伝わらないよう、実験は同時期に近接して実施するか、参加者間での事前の情報交換を禁止する注意書きを入れる）。
- A群には「公式ドキュメント・Web検索のみ使用可。本システムや汎用AIチャットボット（ChatGPT等）の使用は禁止」と明記する。
- B群には「本システムを使用すること。公式ドキュメント・Web検索・他の汎用AIチャットボットの併用は禁止」と明記する（B群がA群の手段も併用してしまうと、システム単体の効果が測れなくなる）。

### 4.6 実験者の中立性

- タスク中、実験者はヒントを与えない。質問には「わかりません。タスク文の範囲で進めてください」等、定型文でのみ応答する。
- 可能であれば記録者と説明担当を分け、記録者には参加者がA/Bどちらかを伏せる（簡易ブラインド）。人手が足りない場合は進行スクリプトの固定を最低限の代替策とする。

## 5. 測定指標の定義

課題シートのアンケート骨格（事前／タスク中ログ／タスク後）に新しい項目を追加するのではなく、それぞれを「何のために測るか」「どう数値化するか」の観点で整理する。

### 5.1 客観指標

| 指標 | 定義・記録方法 |
|---|---|
| 所要時間 | タスク開始から完成条件を満たすまでの時間（分）。未完了の場合は上限時間で打ち切り、「未完了」フラグを別途記録する |
| 操作ミス回数 | 誤操作（削除→取り消し、パラメータ入力ミスの修正、誤ったノード接続のやり直し等）の発生回数。実施者が観察記録するか、Houdini操作ログ（Undo履歴）から集計する |
| 問い合わせ回数 | A群：Web検索の実行回数（検索バーの入力回数）。B群：チャットボットへの質問回数。「何回、外部の助けを求めたか」という同一概念を両群で計測する |

いずれも実験者の観察と、可能な場合はスクリーン録画・操作ログから事後に検証できる形で残す（過少/過多カウントのブレを減らす）。

### 5.2 主観指標（タスク後アンケート、5段階Likert）

課題シートに記載済みの項目をそのまま使用する（項目の追加・変更は行わない）。

| 項目 | 尺度 |
|---|---|
| 難しさ | 5段階（1=非常に易しい〜5=非常に難しい） |
| わかりやすさ | 5段階（1=非常にわかりにくい〜5=非常にわかりやすい） |
| 作業への集中を妨げたか | 5段階または二値 |
| 回答の正確性への不安（ハルシネーション認知） | 5段階（B群のみ、または両群で「情報源への不安」として比較可能な形にする） |
| 提示ソースの有用性 | 5段階（B群のみ。A群には「検索で見つけた情報の中で役に立ったソースはあったか」を対応質問として用意すると比較可能になる） |
| また使いたいか（受容性） | 5段階（B群は「本システムを」、A群は「今回の情報収集方法を」に置き換えて対応質問にする） |

**A群固有／B群固有の項目がある点に注意：** 「ソースの有用性」「また使いたいか」等はB群専用の文言になりがちだが、A群にも意味的に対応する質問（検索で見つけた情報源は役に立ったか等）を用意しておくと、群間比較ができる指標が増える。すでにA群/B群専用でよいと課題シートで確定している項目（ハルシネーション不安など）は無理に対応させなくてよい。

## 6. サンプルサイズ・検出力の目安

卒業研究の実施規模（東京校・名古屋校のCGコース学生が対象）では、大規模な検出力分析通りの人数確保は非現実的なため、簡易的な目安として位置づける。

### 6.1 前提

- 主要指標はノンパラメトリック検定（Mann-Whitney U、[§7](#7-統計解析計画)参照）を用いる。
- 効果量の目安として、介入効果が中程度〜大きい（Cohen's d換算で0.7〜1.0程度）と仮定する。RAG+MCPによる手順提示は「情報の有無」という明確な差を作る介入であり、中間発表段階の期待（わかりやすさの向上・難しさの低減）からもこの程度の効果を想定するのが妥当。

### 6.2 目安表（両側α=0.05、power=0.80、各群同人数の場合）

| 想定効果量（d相当） | 必要人数（各群） |
|---|---|
| d = 1.0（大きい効果） | 各群 約17名 |
| d = 0.8（中〜大） | 各群 約26名 |
| d = 0.5（中程度） | 各群 約64名 |

（t検定近似値にMann-Whitney Uのefficiency loss（正規分布下で約5%程度落ちる）を加味した概算。厳密な検出力計算はソフトウェア（G*Power等）で再確認することを推奨するが、卒業研究の計画段階の目安としてはこの表で足りる。）

### 6.3 現実的な目標人数

- 両校合わせて各群12〜15名（合計24〜30名）を募集目標とする。
- この人数で検出できるのは概ね d≧1.0程度の大きな効果に限られる。**目標人数に届かない場合、あるいは効果量が中程度以下だった場合は、統計的に有意差が出なくても「効果なし」と結論しない**（検出力不足による第二種の過誤の可能性を明記する）。
- 主要な結論は統計的検定の結果と記述統計（平均・分布・個人差の可視化）の両方を併記し、小サンプルであることを踏まえた慎重な言い回しにする。

## 7. 統計解析計画

### 7.1 各指標の検定手法

対象者数が少ないCGコース学生が母集団であり、5段階Likertや回数データは正規性を仮定しにくいため、**ノンパラメトリック検定を基本方針**とする。

| 指標 | 尺度 | 検定手法 | 補足 |
|---|---|---|---|
| わかりやすさ（5段階） | 順序尺度 | Mann-Whitney U検定 | 主要指標(Primary) |
| 難しさ（5段階） | 順序尺度 | Mann-Whitney U検定 | 主要指標(Primary) |
| 所要時間 | 連続量 | Mann-Whitney U検定 | 副次指標。分布が歪みやすいためt検定は使わない |
| 操作ミス回数 | 非負整数（カウント） | Mann-Whitney U検定 | 副次指標。参考として負の二項回帰も可（サンプルが確保できた場合のみ） |
| 問い合わせ回数 | 非負整数（カウント） | Mann-Whitney U検定 | 副次指標 |
| 集中を妨げたか | 5段階 or 二値 | Mann-Whitney U検定（5段階）／Fisherの正確検定（二値） | 副次指標 |
| 回答正確性への不安 | 5段階 | 記述統計＋群内分布の提示（B群固有項目のため群間検定は基本的に対象外） | 副次・探索的 |
| ソースの有用性 | 5段階 | A群対応質問があればMann-Whitney U、なければ群内記述統計のみ | 副次・探索的 |
| また使いたいか（受容性） | 5段階 | Mann-Whitney U検定（対応質問がある場合） | 副次指標 |

**Mann-Whitney Uを基本としつつ、群ごとに分布の形（分散・歪み）が大きく異なりそうな指標（特に所要時間・回数データ）については、Brunner-Munzel検定も参考値として併記する**（Mann-Whitney Uは等分散に近い分布を仮定するため、分布形状が群間で大きく異なる場合はBrunner-Munzelの方が頑健）。

効果量は、p値だけでなく必ず以下も併記する：
- 順位相関に基づく効果量（rank-biserial correlation、あるいはCliff's delta）
- 群ごとの中央値・四分位範囲（IQR）

### 7.2 有意水準・多重比較の補正

- 基本の有意水準は両側 **α=0.05**。
- 主要指標を「わかりやすさ」「難しさ」の2つに限定する（課題シートの「期待される結果」に明記されている2項目のため、これをPrimary endpointとする）。2つの主要指標に対しては **Holm法**による多重比較補正を適用する（Bonferroniより検出力を保てるため）。
  - 具体的には、2つのp値を小さい順に並べ、最小のp値をα/2=0.025で判定、2番目のp値をα/1=0.05で判定する。
- 副次指標（所要時間・操作ミス回数・問い合わせ回数・集中妨害・不安・ソース有用性・受容性）は**探索的（exploratory）**として扱い、多重比較補正はかけずp値をそのまま報告するが、レポート上で「探索的所見であり単独では結論の根拠にしない」ことを明記する。

### 7.3 統合判定ロジック（学習コスト削減効果ありと言えるか）

複数の指標がある場合の最終結論を、以下の優先順位で判定する（トライアンギュレーション：主要指標を軸に、副次指標で裏付けを取る構造）。

```
判定フロー:

Step 1. 主要指標（わかりやすさ・難しさ）をHolm補正後の基準で判定
   ├─ 少なくとも1つがB群優位で有意（補正後 p<.05）
   │  かつ、もう一方の主要指標がB群劣位で有意になっていない（＝悪化していない）
   │  → Step 2 へ
   │
   └─ 両方とも有意差なし、または有意にA群優位
      → 「本システムに主観的な学習コスト削減効果は確認されなかった」
        （副次指標に強い一貫した傾向があれば「限定的な効果」の可能性として考察に記載）

Step 2. 副次指標（所要時間・操作ミス回数・問い合わせ回数）の傾向を確認
   ├─ 複数の副次指標がB群優位の方向で一致している
   │  → 「主観的なわかりやすさ向上に加え、客観的な効率化の傾向も確認された」
   │     （学習コスト削減効果ありと結論。副次指標が有意でなくても「方向が一致」を根拠にする）
   │
   └─ 副次指標が主要指標と矛盾する方向（例：わかりやすさは高いが所要時間はB群の方が長い）
      → 「主観的な学習コスト削減効果は確認されたが、客観的な効率化とは必ずしも一致しない」
        と条件付きで結論し、考察で原因（システム利用そのものの操作コスト等）を検討する

Step 3. 受容性・信頼性系の指標（また使いたいか・ソース有用性・不安）は
        結論の"補強材料"として記述する（これら単独では効果の有無を判定しない）
```

**判定の考え方の要点：**
- 「学習コスト削減効果があった」と言えるのは、あくまで主要指標（わかりやすさ・難しさ）で有意差が確認された場合であり、副次指標だけで結論を出さない（課題シートで学習コストを主観評価と定義しているため）。
- 主要・副次の指標が同じ方向を向いている場合は結論の確度が上がる、逆方向の場合は「効果はあるが一様ではない」という条件付きの結論にする。
- サンプルサイズが目標に届かなかった場合（[§6.3](#63-現実的な目標人数)）は、有意差が出なくても「効果なし」ではなく「検出力不足のため判定不能／今後の再現実験が必要」という表現にする。

## 9. 倫理・データ取扱い

課題シートの記述「本アンケート調査では個人情報の収集や侵襲デバイスの利用は行わない」を前提に、以下を運用ルールとする。

- **説明・同意：** 実験の目的・所要時間・タスク内容の概要・参加は任意で中断可能なこと・データの使途（卒業論文・中間発表での使用）を口頭または文書で説明し、同意を得た上で実施する。個人情報を収集しないため署名式の同意書までは必須ではないが、口頭同意の記録（実施日・参加者数のみ）は残す。
- **匿名化：** 参加者は氏名ではなく参加者ID（T-01, N-01等、校舎+連番）で管理する。年齢・学籍番号等は収集しない。事前アンケートの「学習背景・技術的背景・実務経験」も個人が特定できない粒度（年数・有無等の範囲回答）で収集する。
- **データ保存：** タスク中ログ・アンケート回答は参加者IDに紐付けて集計用データとして保存し、論文・発表資料には集計値（平均・中央値・分布）のみを掲載する。個々の回答を個人が識別可能な形で公開しない。
- **撤回：** タスク中・アンケート回答中いつでも中断・撤回できることを事前に伝える。
- **侵襲デバイス不使用の確認：** 視線計測・生体センサー等は使用しない。操作ログはHoudiniの操作記録・実施者の観察記録・画面録画（任意、参加者に別途同意を得た場合のみ）に限る。

## 10. 既知の限界・バイアスリスクと対策

| リスク | 内容 | 緩和策 |
|---|---|---|
| サンプルサイズ | 卒業研究の規模では[§6](#6-サンプルサイズ検出力の目安)の目標人数に届かない可能性が高い | 統計的検定に加え記述統計・分布の可視化を必ず併記し、検出力不足の場合はその旨を明記する |
| 実験者バイアス | 実験者＝システム開発者本人であることによる期待効果（Hawthorne効果） | 進行スクリプトの固定・音声/文書での説明配布・記録者と説明担当の分離（可能な範囲で） |
| 群間の情報漏洩 | A群参加者が実験前後にB群からシステムの存在・使い方を聞いてしまう | 実施を近接した期間に集約し、参加者間の情報交換を控える注意書きを入れる |
| 実施環境差 | 校舎（東京/名古屋）・PC・回線速度の違いが群間差と交絡する | 両校舎でA/B双方を実施し、校舎をA/B割り当てと交絡させない（[§4.4](#44-実施環境の統制)） |
| タスク選定バイアス | 本システムが得意な操作だけを課題に選ぶと結果が偏る | タスク選定基準（バージョン変化の実在・パイロットでの難易度確認）を事前に記録し報告書で開示する |
| 操作ミス・問い合わせ回数のカウント基準のブレ | 実施者の主観でカウント基準が変わる | カウント基準（何を1回とするか）を事前に定義し、可能であれば操作ログ・画面録画で事後検証する |
| 多重比較による疑陽性 | 指標が7項目程度あり、補正なしだと偶然の有意差が出やすい | 主要指標2つにHolm補正、副次指標は探索的として扱う（[§7.2](#72-有意水準多重比較の補正)） |

## 11. 未確定事項（要判断）

以下は課題シートやこれまでの合意事項からは決められないため、実施前に確認・決定する必要がある。

1. **タスクの具体的な選定：** バージョン変化で手順が変わった操作を実際に何にするか（候補の洗い出しとパイロットでの難易度確認が必要）
2. **時間制限の具体的な分数：** パイロット結果を見てから確定する
3. **東京校・名古屋校それぞれの募集人数の内訳：** 両校でA/B比が偏らないように調整する必要があるが、募集のしやすさは現地でないと分からない
4. **画面録画・操作ログの取得可否：** Houdini操作ログの自動取得（Undo履歴等）が技術的にどこまで可能か、実装側（`houdini/python_panels/`）の対応状況を確認する
5. **謝礼・インセンティブの有無：** 参加率に影響するため早めに決める
6. **倫理審査の要否：** 所属機関に人を対象とした研究の審査手続きがあるか確認する（個人情報を収集しない設計のため簡易審査で済む可能性はあるが要確認）
