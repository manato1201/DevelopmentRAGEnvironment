# 第4回 RAG と AI の API（埋め込み・ハイブリッド検索・回答・出典・予算）

**到達目標:** [図11](../../images/11-request-life.svg) の **6（予算の確保）〜10（精算・保存）** と、[図03](../../images/03-rag-flow.svg) の検索の流れを、自分の言葉で説明できる。「なぜ、検索結果だけを根拠に答えさせるのか」「なぜ予算を『先に確保して、あとで精算』するのか」を言える。
**前提:** 第1〜3回。 **目安:** 3時間

---

## 1. 全体像

AI（大規模言語モデル）は、**知らないことを、もっともらしく答えてしまう**ことがあります。社内の資料や、最新の Houdini の仕様は、AI は知りません。そこで、**質問に関係する資料を先に探して、AI に渡し、「この資料だけを根拠に答えて。出典の番号をつけて」と頼む**。これが **RAG（検索拡張生成）** です。

[![質問から回答までの流れ](../../images/03-rag-flow.svg)](../../images/03-rag-flow.svg)

## 2. 基礎

### 2.1 LLM・トークン・コンテキスト

- **LLM**: 文章の続きを予測して、文章を作る AI。Claude・Gemini など。
- **トークン**: LLM が数える、文字の単位。日本語は、1文字が1トークン前後。**入力（質問＋渡した資料）と出力（回答）の合計**で、料金と上限が決まります。
- **コンテキスト**: AI に一度に渡せる文章の量。資料を全部渡すことはできないので、**関係する部分だけ**を、探して渡します。

### 2.2 埋め込み（意味を数の列にする）

文章を、**意味の方向を表す数の列（ベクトル）**に変換することを、**埋め込み（embedding）**と言います。意味の近い文章は、近いベクトルになります。

```
「Pyro の煙を消す」   → [0.12, -0.80, 0.33, …] （768個の数）
「煙のシミュレーション」→ [0.10, -0.77, 0.30, …]   ← 近い
「ファイルを保存する」 → [-0.65, 0.20, 0.91, …]   ← 遠い
```

近さは、**コサイン類似度**（ベクトルの向きの近さ）で測ります。このプロジェクトでは、Gemini の埋め込み（`gemini-embedding-001`）を使います（`src/embeddings.ts` の `embedText`）。

### 2.3 チャンク（資料を断片にする）

長い資料は、そのまま埋め込めません（意味が薄まる）。**1000文字ずつ、150文字ずつ重ねて**切り出します（`src/chunking.ts` の `chunkText(text, size = 1000, overlap = 150)`）。重ねるのは、文の途中で切れて、意味が失われるのを避けるためです。

### 2.4 2つの検索と、その統合

| | 意味検索（Vectorize） | キーワード検索（D1 の FTS5） |
|---|---|---|
| しくみ | ベクトルが近いものを探す | 文字（単語）が一致するものを探す（BM25） |
| 得意 | 言い換え・曖昧な質問 | 固有名詞・型番・エラーメッセージ |
| 苦手 | 固有名詞の一致 | 言い換え |

両方で探し、**順位を統合**します。これが**ハイブリッド検索**です。統合は **RRF（Reciprocal Rank Fusion）**。各リストでの**順位**だけを使って点を付け（`1 / (k + 順位)`、`k = 60`）、足し合わせます（`src/hybrid.ts` の `rrfMerge`）。点数の尺度が違う2つの検索を、**順位だけ**で公平に混ぜられるのが利点です。

### 2.5 HyDE（仮の回答で探す）

質問文は短く、資料の文とは、書き方が違います。そこで、**まず AI に「仮の回答」を書かせ**、その仮回答を埋め込んで探します（**H**ypothetical **D**ocument **E**mbeddings）。質問より、資料に近い文になるので、見つかりやすくなります（`hydeExpand`。温度 0 で、毎回同じ結果になるようにしてある）。

### 2.6 回答の生成と「出典」

資料（チャンク）を、**番号つきで**プロンプトに入れます。

```
[1] （資料A の断片）…
[2] （資料B の断片）…
質問: …
指示: 上の資料だけを根拠に答える。根拠にした資料は [1] [2] の番号で示す。資料に無いことは「分からない」と言う。
```

- 回答に `[1]` `[2]` が出てくれば、**どの資料を根拠にしたか**が分かります（画面の「出典」）。
- **採用比率**（`extractionRate`）= 回答で使った資料 ÷ 検索で見つかった資料。**引用が1つも無い回答は、出典を示さずに答えている可能性**があるので、警告します（`panel_info.py` の `summarize_sources`）。
- 検索で何も見つからなかったとき、AI に自由に答えさせず、**「見つかりませんでした」**で返すのが安全です。

### 2.7 namespace（知識の置き場の名前）

資料は、**namespace** で分かれます（`houdini22`・`shared:tool_docs`・`personal:<user_id>`…）。**キーごとに、使える namespace が決まっています**（`key_namespace_grants`）。他人の `personal:` は、読めません。検索は、まず「**この人が使える namespace**」に絞ってから行います（`resolveEffectiveNamespaces`）。

### 2.8 予算：先に確保して、あとで精算する

AI の利用には、お金がかかります。**キーごとのトークン予算**（`token_budgets`）で、使いすぎを止めます。ここに、**同時に何回も質問された**ときの落とし穴があります。

- 悪い実装: ① 予算が残っているか確認 → ② AI を呼ぶ → ③ 使った分を引く。
  → 同時に10回来ると、10回とも①を通過して、**予算を超えて使えてしまう**（確認と引き算の間に、すき間がある）。
- このプロジェクトの実装（`src/budget.ts`）:
  1. **`reserveBudget`**: **見積もり分（RAG は 4000 トークン）を、先に引く**。SQL 1文で、「残りが足りるときだけ加算」する（`UPDATE … SET used = used + ? WHERE used + ? <= limit`）。足りなければ、変更が0行 → 429。
  2. 処理する。
  3. **`reconcileBudget`**: 実測との**差分だけ**を、戻す（少なく使った）か、足す（多く使った）。
  4. 失敗したときは、確保した分を**全額戻す**。

> 学び: 「確認してから引く」を、**1つの原子的な操作**にする（確認と更新を、1つの SQL にする）。

### 2.9 説明レベルと習熟度（成長）

同じ質問でも、初心者と上級者で、**ふさわしい説明が違います**。`src/growth.ts` は、質問に含まれる**専門用語**を数え（`user_terms`）、点数にして、**basic（6点未満）・applied（6点以上）・advanced（18点以上）**を決めます。「役に立たなかった」（👎）が**3回続く**と、一段やさしくします。これで、プロンプトに「説明のレベル」を足します。

## 5. つまずきやすい点

- **「検索結果が少ない = 悪い」とは限らない。** 低い一致を除くのは、わざと（**関係ない資料で、AI が惑わされる**のを防ぐ）。
- **AI の回答を、そのまま信じる。** 出典の番号と、元の資料で確かめる（画面にも、そう書いてある）。
- **namespace を、全部指定したつもりで、権限が無くて 0 件。** キーの許可（`key_namespace_grants`）を確認する。
- **見積もりが小さすぎる。** 実測が上回ると、`reconcileBudget` が追加で引くので、予算が**マイナス方向に超える**ことが、ありうる。見積もりは、やや多めにする。

2. RRF が、点数でなく順位を使う理由は？
3. チャンクを重ねる理由は？
4. 予算を「先に確保」する理由は？
5. 「引用が1つも無い回答」に、警告を出す理由は？

## 解答の方針

- 4.1: `assertNotRateLimited`（レート制限）→ `startAuditLog`（監査ログ。これ自体が「今、処理中」の予約になる）→ `reserveBudget`（6）→ `retrieve`（7）→ …生成 → `reconcileBudget`（精算）→ `saveMemory`（10）。正確な行は、自分で確かめる。
- 4.3: `1/61 ≈ 0.01639`（A の1位のみ）、`1/61 + 1/63 ≈ 0.03226`（両方に載る）。**両方に載った文書のほうが上位**。
- 4.4: 点数 17.5 は applied（6 以上 18 未満）。直近3回が👎で、`scoreLevel !== "basic"` なので、一段下げて **basic**。
- 4.5: 同時に多数の質問が来ると、全部が確認を通過して、**予算を超えて使えてしまう**。
- 確認問題 3: 文の途中で切れて、意味が失われるのを避けるため。
