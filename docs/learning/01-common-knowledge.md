## 1. コンピュータとOSの常識

| 用語 | 一言で | このプロジェクトでの出番 |
|------|--------|--------------------------|
| プロセス | 動いているプログラム | `wrangler dev`、`rag_local_bridge.py`、Houdini本体 |
| 環境変数 | プログラムに渡す、名前つきの設定値 | `ANTHROPIC_API_KEY`（鍵を、ファイルではなく環境変数に置く方針） |
| PATH | コマンドを探す場所の一覧 | `uv`、`node`、`ffmpeg` が見つからないときは、まずPATH |
| 標準出力・標準エラー | プログラムが書き出す結果・エラー | `wrangler`のログ、`uv run`の出力 |
| 終了コード | 成功は0、失敗は0以外 | `tsc --noEmit`が0以外なら型エラー |
| 権限 | 誰が何をできるか | OSのファイル権限、APIキーのロール（admin/editor/member/guest） |

**文字コードと改行（ハマりやすい）**
- テキストは **UTF-8** で保存する。日本語が文字化けしたら、まず保存時の文字コードを疑う。
- 改行はOSで違う。Windowsは `CRLF`（`\r\n`）、LinuxやMacは `LF`（`\n`）。ファイルの中に両方が混ざると、検索・置換や差分が合わなくなる。このプロジェクトでも、置換スクリプトが改行の違いで失敗したことがある。
- Windowsのパスは `C:\Users\...`（バックスラッシュ）。プログラムの文字列に書くと、`\` が特別な意味（エスケープ）になる。パスは `/` で書くか、`\\` と二重にする。

## 2. ネットワークとWebの常識

### 2.1 URLとHTTP

```
https://rag-poc.manato1201m.workers.dev/query?x=1
└─┬──┘ └──────────────┬──────────────┘└──┬─┘ └┬─┘
 通信方式          ホスト名             パス  クエリ
```

- **リクエスト**は「メソッド（GET/POSTなど）＋URL＋ヘッダ＋本文」。**レスポンス**は「ステータスコード＋ヘッダ＋本文」。
- このプロジェクトのAPIは、ほとんどが `POST`＋JSON本文。認証は `Authorization: Bearer <APIキー>` ヘッダ。

| ステータス | 意味 | このプロジェクトでの典型 |
|---|---|---|
| 200 | 成功 | |
| 400 | リクエストが不正 | 必須項目が無い |
| 401 | 認証できない | APIキーが違う・期限切れ |
| 403 | 権限が無い | memberがadmin用APIを呼んだ |
| 404 | 見つからない | 存在しないドキュメントの削除 |
| 405 | そのメソッドは使えない | POST専用のURLをGETで開いた |
| 429 | 回数・予算の超過 | レート制限、トークン予算 |
| 500 | サーバー内部の失敗 | コードの例外、**D1の上限超過** |
| 503 | 一時的に使えない | 設定不足、一時的な障害 |

### 2.2 「応答がJSONではありません」の正体

画面に出る `Unexpected token '<'` や「応答がJSONではありません」は、**サーバーがJSONではなくHTMLのエラーページを返した**ときに出る。`<` は `<html>` の先頭。原因は大きく2つ。

1. 処理に時間がかかり、途中のプロキシ・ブラウザが打ち切った（タイムアウト）。
2. サーバー（Worker）が、JSONを作る前に落ちた（Cloudflareのエラーページ）。

→ **まずステータスコードを見る**（ブラウザの開発者ツール → Networkタブ）。500なら、サーバー側の問題。

### 2.3 DNS・HTTPS・CORSを一言で

- **DNS:** ホスト名からIPアドレスを調べる仕組み。「名前が解決できない」はDNSの問題。
- **HTTPS:** 通信の暗号化。鍵（APIキー）を送るときは必ずHTTPS。`http://`に鍵を送らない。
- **CORS:** ブラウザが、別のサイトへのリクエストを制限する仕組み。ブラウザだけの制限なので、`curl`では起きない。「curlでは通るのにブラウザでは失敗する」ときに疑う。

## 3. データ形式の常識

| 形式 | 特徴 | 出番 |
|---|---|---|
| JSON | `{ "名前": 値 }`。文字列は`"`で囲む。末尾にカンマ不可。コメント不可 | API、設定ファイル |
| Markdown | 見出し・リスト・コードを簡単に書く | 資料、チュートリアルの出力 |
| CSV | カンマ区切りの表 | Q&Aの一括登録、利用状況のエクスポート |
| SQL | データベースへの命令 | `migrations/`、`wrangler d1 execute` |
| YAML/TOML | 設定向け。インデントが意味を持つ | `pyproject.toml`、GitHub Actions |
| Base64 | バイナリを文字にする | 画像・ファイルをJSONに載せるとき（約33%大きくなる） |

## 4. セキュリティの常識

1. **秘密（APIキー・トークン・パスワード）はコードに書かない・Gitに入れない。** 置き場所: Cloudflareなら `wrangler secret put`、ローカルなら環境変数。鍵を見つけたら、**使えなくして（失効）、新しく作り直す**。履歴から消しても、一度公開した鍵は漏れたものとして扱う。
2. **最小権限。** 必要な権限だけ渡す。このプロジェクトでは、APIキーごとに「見られるnamespace」を許可リストで絞る。連携の同期先も、許可リストに入れたものだけ。
3. **入力を信用しない。** 外から来る値は、型・長さ・範囲を確認する。`clampInt`（`src/http.ts`）はその例。SQLには、値を文字列で埋め込まず、必ず `?` と `bind` で渡す（SQLインジェクション対策）。
4. **画面に出す文字はエスケープする。** 外部の文章がそのままHTMLとして実行されると、不正なスクリプトが動く（XSS）。`oauthResultPage` は、メッセージをエスケープしている。
5. **プロンプトインジェクション。** AIに読ませる文書や、外部ツールの結果の中に「この指示に従え」と書かれていても、**それは命令ではなくデータ**。このプロジェクトでは、外部連携のツールを読み取り専用にし、書き込み系は使わせない。
6. **署名で本物かを確かめる。** SlackからのリクエストはHMAC署名（秘密の値で作る改ざん検出）と時刻で確認する。
7. **鍵の表示は、必要な時間だけ。** 管理画面は、発行した鍵を60秒で隠す。

**漏れたかもしれないとき（手順）:** ①その鍵を失効 → ②新しい鍵を発行して置き換え → ③監査ログで、いつ・何に使われたか確認 → ④再発防止（置き場所の見直し）。

## 5. Gitの常識

| やりたいこと | コマンド | 注意 |
|---|---|---|
| 状態を見る | `git status` | 迷ったら、まずこれ |
| 変更の中身を見る | `git diff` | コミット前に必ず読む |
| 記録する | `git add <ファイル>` → `git commit -m "メッセージ"` | `git add .` は、意図しないファイルを入れやすい |
| 履歴を見る | `git log --oneline -10` | 書き方（`feat:` など）は、既存に合わせる |
| 直前の変更を取り消す（新しい記録で） | `git revert <コミット>` | 履歴を消さないので安全 |
| 変更を捨てる | `git restore <ファイル>` | **戻せない**。捨ててよいと確認してから |

- `.gitignore` に書いたファイルは追跡されない（`data/`、ローカルのvault、`.wrangler/` など）。
- コミットは**意味のある単位**で。「バグ修正」と「整形」を混ぜない。
- `git push --force` や `git reset --hard` は、他の人の作業や自分の未保存の作業を消す。使う前に、必ず何が消えるかを確認する。

## 6. 仕事の進め方の常識

1. **再現手順を作ってから直す。** 「いつ・何をしたら・何が起きたか」を、他の人が同じにできる形で書く。直した後に、同じ手順で直ったことを確かめる。
2. **ログを読む。** 画面の文言の次に、ログ（`wrangler tail`、ブラウザのConsole）。
3. **本番と開発を区別する。** コマンドに `--remote` が付くか、URLが本番か、毎回確認する。
4. **変更の前に、戻し方を決める。** バックアップ、`git`、マイグレーションは追加のみ、など。
5. **直す順番:** 影響の大きいもの → 原因が分かるもの → 手間が小さいもの。
6. **分からないことは、実験で確かめる。** ただし、実験は、壊れても良い場所（ローカル・コピー）で。

## 7. 費用と上限の常識

クラウドの多くは「無料枠」と「従量課金」でできている。**上限に達したときのふるまい**を、使う前に知っておく。

| サービス | 上限の例 | 達すると |
|---|---|---|
| Cloudflare D1（無料枠） | 1日の読み取り行数（500万行）・書き込み行数 | **すべてのデータベースの呼び出しが失敗**（本プロジェクトで2026-10-16に実際に発生し、全APIが500を返した） |
| Cloudflare Workers（無料枠） | 1リクエストのCPU時間、外部呼び出し数、1日のリクエスト数 | そのリクエストが失敗（`Error 1102`など） |
| Gemini / Claude API | トークン数（入力＋出力）に応じた従量課金 | 課金が増える。このプロジェクトは、APIキーごとの予算で、サーバー側が止める |

- **上限は日・月で戻る。** D1の無料枠は、UTC 0時（日本時間9時）に戻る。
- **「全部が壊れた」ときは、まず上限を疑う。** コードの変更が無いのに、急に全部が失敗したときは、特に。
- 数字は変わる。**使う前に公式ページで最新を確認する**（[D1の制限](https://developers.cloudflare.com/d1/platform/limits/)）。

## 練習

1. ブラウザの開発者ツールを開き、管理画面で何かの操作をして、Networkタブでリクエスト1つを選ぶ。メソッド・URL・ステータス・レスポンスの本文を、それぞれ書き出す。
2. [`src/http.ts`](../../cloudflare-rag-poc/src/http.ts) の `jsonResponse` が返すレスポンスの、ステータス・ヘッダ・本文を、言葉で説明する。
3. `git log --oneline -10` を実行し、コミットメッセージの書き方の規則を、1行で説明する。
4. 「APIキーを誤ってチャットに貼ってしまった」とき、§4の手順を、このプロジェクトの具体的な操作（管理画面のどのボタンか）に置き換えて書く。（[user-manual.md](../user-manual.md)を参照）
5. 「Workersの`1102`エラー」と「D1の上限超過」は、どちらも画面では「500」に見える。どうやって区別するか、考える。

**ヒント:** 1は、Network → 対象を選ぶ → Headers／Response。2は、`content-type`ヘッダに注目。3は、`feat:` `fix:` `docs:` の有無。5は、エラーメッセージの文言（[06-maintenance-runbook.md](06-maintenance-runbook.md)の障害記録）。
