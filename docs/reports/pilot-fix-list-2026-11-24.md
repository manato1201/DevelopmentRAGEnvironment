## B. 集計の外で見つかった不具合

### B1. チュートリアル生成中に操作すると、崩れる

- **何が起きるか**: 生成の最中に、Houdini を触ると、結果が崩れる（利用者の報告。詳しい症状は未確認）。
- **コードで確かめたこと**
  - 生成は別スレッド（`TutorialWorker`）で動き、Houdini の操作は `hdefereval` でメインスレッドへ送っている（`houdini_tools.py` `_run_in_main_thread`）。
  - 撮影のために、ペインを最大化し、`hou.ui.waitUntil` と `processEvents` で待つ（`screen_capture.py` `maximized_if_narrow`・`_wait_for_ui`）。**待っているあいだは、利用者の操作（ノードの選択・ペインの切り替え・時間の移動）も処理される。** 撮影・cook の途中に割り込める。
  - 生成の最初に、`/obj` 直下の、ほかのオブジェクトの表示を切る（`display_isolation.isolate`）。生成中にネットワークを動かすと、表示の状態とずれる。
- **直し方（案）**
  1. 生成中は、パネルに「操作しないでください」の帯を出す（A1 と共通）。
  2. 撮影の前後で、ペインの状態・選択・現在のノード・フレームを保存して、必ず戻す（`try/finally`）。
  3. 撮影の前に、選択や現在のネットワークが変わっていたら、撮り直す（変わったことを検出する）。
- **要る情報**: 崩れたときの、操作の内容（何を触ったか）と、Houdini のコンソールの出力。

### B2. たまに、タブ以外の操作ができなくなる

- **何が起きるか**: ときどき、タブの切り替えしかできなくなる（利用者の報告）。**チュートリアル生成のあと、または動画生成のあとに起きる**（利用者の追記、2026-11-24）。
- **コードで確かめたこと（追記）**: 入力を奪う仕組み（イベントフィルタ・キー入力の独占・モーダル表示）は、パネルのコードに見つからなかった。生成の完了で動くものは、次のとおり。
  - チュートリアル生成の完了: `_on_done`（利用量の記録 → ボタンを戻す。途中の例外で、戻らない）と、Guide タブへの自動の切り替え（`_announce_guide`。例外は握りつぶす）。
  - 動画生成の完了: `VideoScriptWorker` の `on_done` と、ログを 2 秒ごとに読む `poll()`（`tutorial_view.py` 1360・1469 行）。どちらも、例外を受ける `try` が無い。例外が出ると、その場で処理が止まり、画面には何も出ない。
- **原因の候補（まだ確かめていない。上から可能性が高い順）**
  1. **完了の処理で例外が出て、ボタンが無効のまま残る。** `tutorial_view.py` の `_on_done` は、`record_usage`・`save_server_quota`・`_refresh_usage` を呼んだ**あとに**、`_generate_btn.setEnabled(True)` を呼ぶ。途中で例外が出ると、生成ボタンも保存ボタンも無効のまま。チャットも同じ形（`rag_chatbot.py` `_on_query_done` は、回答の表示を作ったあとに `_send_btn.setEnabled(True)`）。例外は、Qt のスロットの中で出るため、画面には何も出ない。
  2. **待ちの入れ子のあいだに、別の操作が入り込む。** B1 と同じ仕組み（`waitUntil`）。生成中に別の生成・保存を押すと、状態が壊れる。
  3. **ペインの最大化・前面化の戻し忘れ。** `maximized_if_narrow` は元に戻すが、`pane.setIsMaximized(False)` が失敗すると、ログだけ残して進む。前面化は、Alt キーの押下を送っている（`_force_foreground`）。
- **直し方（案）**
  0. **まず、記録を足す。** Qt のスロットの例外を、デバッグログに残す（`sys.excepthook`）。完了の処理の入口・出口にも、1 行ずつ記録する。次に起きたとき、どこで止まったかが分かる。
  1. 完了・失敗のスロット（`_on_done`・`_on_chain_done`・`on_done`・`poll`）は、`try/finally` で、ボタンを必ず戻す。例外は、デバッグログ（メニュー ≡ →「デバッグ」）に残す。
  2. 生成中は、Houdini を動かす操作のボタン（Reference・Guide・パイロットの課題など）も、無効にする（いまは、生成・保存・破棄などの一部だけ。`tutorial_view.py` 1046〜1048 行）。
  3. 「ボタンが無効のまま」を検出して、一定時間で戻す見張りを入れる。
- **要る情報**: 症状が出たときの、Houdini のコンソール（Python の例外）と、パネルのデバッグログ。出たときに、チャットの送信ボタンと、生成ボタンのどちらが灰色かを見てもらうと、候補 1 かどうかが分かる。

**原因（コードで確認、偽の Houdini で再現）:** Guide の「作る手順」（`create_node`）が、ネットワークエディタを、**手順のパスで一番深い既存の階層**へ移す（`guide_mode.apply_step` の `editor.setPwd(h.container)`、`_search_base` の `_deepest_existing`）。手順のパスは、サンドボックス相対（例: `geo1/scatter2`）で、学習者が自分の名前（例: `pyro_geo`）で作業していると、`/obj/geo1` が無いので、一番深い既存の階層は `/obj` になる。表示は、そこへ戻る（「/obj を開きました。ここで Tab を押して作ります」と出る）。

**再現手順（Houdini の画面）**
1. チュートリアルを生成するか、保存済みのものを読み込む（作る手順に、`geo1/…` のようなパスが入っているもの）。
2. Guide タブで、「自動で案内」をオンにする。
3. Houdini で、手順とは**違う名前**のオブジェクト（例: `pyro_geo`）を作り、その中に入って作業する。
4. Guide の「次へ」（または、チェックで手順を進める）で、「作る手順」へ進む。
5. ネットワークエディタが、`/obj` に戻る。

**偽の Houdini での再現:** 作業中 `/obj/pyro_geo` → 手順のあと `/obj`（手順と同じ名前 `geo1` で作業しているときは、`/obj/geo1` のまま）。再現のスクリプトは、`build/sim/repro_a2.py`（リポジトリの外）。

**直し方（案）:** 手順の階層が見つからないとき、いまのネットワークが、`/obj` の下の、どこかの階層（自分の作業場所）なら、**動かさない**。動かすのは、いまの場所が `/obj` の外・手順の階層の外のときだけ。メッセージも、「手順は `/obj/geo1` で作りますが、いまの `/obj/pyro_geo` で作れます」と、移さずに伝える。
