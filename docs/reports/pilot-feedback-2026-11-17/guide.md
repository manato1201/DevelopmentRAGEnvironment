# guide（前と後の差）

Houdini の「Guide」タブ（手順ガイド）の担当。Houdini の実機は無いため、Houdini 依存の部分は偽物（`houdini/tests/guide_fakes.py`）で確かめた。実機での確認は、末尾の「未対応・要確認」に分けて書いた。

## 項目ごとの差

### 1. ガイドで、違うオブジェクトが表示される問題（対応オブジェクトで表示・追従）
- **前**: 手順が指すノードを、**名前（なければ種類）だけ**で探していた（`guide_mode.find_node`）。次の4つの原因を、再現テストで確認した（直す前は4件とも失敗）。
  1. **同じ種類の別ノードを拾う**: 探し方が「名前が合う → 無ければ、種類が同じ最初のノード」だった。`scatter2` を「作る」手順で、すでにある `scatter1` が「操作するノード」として選ばれた（`test_create_step_does_not_select_another_node_of_the_same_type`）。
  2. **ほかの場所の同名ノードを拾う**: `/obj` 全体を探し、最初に見つかった同名のノードを返していた。前回の生成のサンドボックス（`/obj/ai_tutorial_<日時>/…`）に同じ名前（例 `vortex_points`）があると、そちらが選ばれた（`test_the_same_name_in_an_older_sandbox_is_not_picked`）。
  3. **順序**: ノードを先に選び、**あとで**ネットワークエディタを切り替えていた（`show_nodes`）。切り替えのあとに選ばないと、パラメータ画面が別のノードのままになりうる（`test_the_network_is_switched_before_the_node_is_made_current`）。
  4. **ピン留め**: パラメータ画面がピンで固定されていると、選んだノードに追従しない。外す処理が無かった（`test_a_pinned_parameter_pane_is_released`）。
  - 案内データに、探すための情報も足りなかった（ノードの名前だけ。サンドボックスのパスが保存されていない）。
  - 補足（推測）: スクリーンショットの Guide タブが、手順と合っていなかった直接の原因は、上の 1・2 のどちらか、または両方と考えられる（実機の状態は確認できていない）。
- **後**: `guide_mode.resolve_step_target` を新設し、次の順で探す。当て推量では選ばない。
  1. **パスが一致**: 手順のパス（サンドボックス相対）を、根につなぐ。学習者の根は `/obj`、サンドボックスの根は案内データに保存した `sandbox_path`。ノードの**種類も合う**ときだけ採用（名前が同じで種類が違うものは採用せず、理由に書く）。
  2. **名前＋種類が一致**するものが、根の中に**1つだけ**ある（ほかの生成のサンドボックスは、探索から外す）。複数あるときは、手順のパスに最も近い1つが決まるときだけ。決まらなければ、候補を全部（パスで）書いて、選ばない。
  3. **種類が同じ別名**（学習者が名前を変えた場合）: 手順のネットワークに、同じ種類が**1つだけ**のときに限り、「名前が違う同じ種類のノードを示しました」と断って示す。
  4. **作る手順（create_node）**: すでにある別のノードを示さない。作る場所（ネットワーク）だけ開き、「まだありません。ここで Tab を押して作ります」と出す。
  - 見つからないとき: 理由を画面に出す（「『vortex_points』（/obj/geo1/vortex_points）は見つかりません。…種類が違います／同じ名前が複数あります（パス）／サンドボックスが見つかりません」）。
  - **案内する場所**の選択（Guide タブ）: 自動（まず自分のネットワーク。無ければ、生成したサンドボックスの実物を「見本です」と断って示す。作る手順は、サンドボックスへ飛ばない）／自分のネットワークだけ／サンドボックスだけ。選択は覚える。
  - **追従**: ネットワークの切り替え → `setCurrent`（選択）→ `editor.setCurrentNode` → 追加の選択、の順にした。ピンで固定されたパラメータ画面は外す（外したと画面に出す）。複数のネットワークエディタがあるときは、前面のものを使う。示したあとに `verify_shown` で、選択とネットワークが合っているか確かめ、合わなければ画面にそう出す。
  - 変更したファイル: `guide_mode.py`（`resolve_step_target`、`focus_nodes`、`verify_shown`、`release_parm_pin`、`apply_step`）、`guide_view.py`（案内する場所の選択、`sandbox_path` を渡す）、`tutorial_view.py`（`sandbox_path` を案内データに保存）。
  - 確認した根拠: `test_guide_target.py`（17件）。上の再現テスト4件が通る。ほかに、パス優先・種類違いは不採用・サンドボックス/自分の切り替え・自動のときの注記・別名は1つだけのとき・同名が複数のとき・理由の文、など。
- **状態**: 完了（偽物での確認まで。実機は未確認）

### 2. UI の強調表示（手順が指すパラメータとノード）
- **前**: ノードを選んで寄せ、タブを前面に出すだけ。パラメータは、どのタブのどの項目かを、案内の「場所」の小さな文字で出すだけで、画面を動かす操作はなかった。
- **後**:
  - ノード: 選択・ネットワークエディタをそのノードに寄せる（`homeToSelection`）・画面に「ここを操作します」の表示（`flashMessage`）。複数ノード（つなぐ手順）は、同じネットワークのものをまとめて選ぶ。
  - パラメータ: パラメータ画面を前面に出し、ノードを現在のノードにし、固定（ピン）を外す。**タブと項目は、画面の文言で補う**（案内の下の欄に「パラメータのタブ: Sourcing > Emission、項目: Run Over（内部名: class）」。タブの外のものは「タブの外（パラメータ画面のいちばん上）」）。案内したときの画面の下にも同じ文を出す。
  - Guide タブの手順の表示: 作業する部分を青い帯、「消す」手順を赤い帯で強調。
  - **できなかったこと**: パラメータ画面の中の「特定のタブを前面に出す」「特定の項目を光らせる」ことは、API を確かめられなかったので、実装していない（推測で書かない）。文言で補っている。
- **状態**: 一部（パラメータ画面内のタブ・項目の強調は、API 未確認のため文言のみ）

### 3. ガイドの表記の改善（感想（3））
- **ショートカットは、最初の手順だけ出し、あとは折りたたむ**
  - 前: 全手順の上に、毎回8〜16個の一覧が出て、見るべき内容を押しのけていた（手順1と手順2で、どちらも「ショートカット」が出ることを確認）。
  - 後: 最初の手順は自動で出す。2番目以降は、1行の案内だけ。「ショートカットを表示」ボタン（トグル）で開く。開いた状態は覚える（`~/.houdini/rag_chatbot_ui.json` の `guide_shortcuts_open`。既存の `ui_state_*`）。「ショートカット一覧」（全部）は、そのまま残した。テスト: `test_shortcuts_are_folded_after_the_first_step`、`test_shortcut_setting_is_remembered_and_folds_later_steps`。
- **パスの省略をしない**
  - 前: つなぐ手順の案内が「n0 → n1、… n5 → n6 ほか」と6本で切れていた（9本で確認）。手順の文も、200文字で切っていた。
  - 後: つなぐ線を、全部（記録は最大12本）、1本ずつ列で出す。手順の文（`instruction`）の切り捨てをやめた。ノードのパスは `/obj/…` の形で全部出す。表示欄は、長いパスを途中で切らずに折り返す（`WrapAtWordBoundaryOrAnywhere`）。テスト: `test_nothing_is_cut_with_an_ellipsis`、`test_connect_step_lists_every_line`。
  - 残る限界: 記録時（`houdini_tools.py`）に、値は60文字、前の値は40文字、つなぐ線は12本で切っている。切れた値は「値が長いため、記録は60文字までです」と、画面に断る。
- **どの階層にいるか（常に表示）**
  - 後: Guide タブの上に常に、「いまのネットワーク: /obj/…」と「この手順の場所: /obj/…（同じ／違います）」を出す。1.5秒ごとに更新（タブが見えているときだけ）。Houdini の外では、手順の場所だけ。手順ごとに「作業するネットワーク（階層）」も出す。
- **チェックボックス・メニューは、表示名で言う**
  - 前: 「Run Over: 0 → 2」のように、数字だけ。
  - 後: `Run Over を Detail (only once) にする`（前の値も表示名: `前の値: Points（値: 0）`）、`Enable をオフにする（チェックを外す。無効にする）`。表示名は、ノード（無ければノードの種類）から `parmTemplate().menuItems()/menuLabels()` で引く（`parm_value_info`、`describe_parm_change`）。引けないときは、数字のまま「Run Over を 2 にする」（メニューかどうかは言わない）。範囲外の値も数字のまま。
- **パラメータの場所**: 上の2の通り（タブ＞折りたたみ、項目、内部名）。
- **消す場合は「消す」**: 削除の手順は、冒頭に「【消す】/obj/…/old_null を削除する」を赤い帯で出す。値を空にするパラメータは「X を空にする（入っている内容を消す）」。チェックを外すものは「オフにする（…無効にする）」。
- **パラメータ調整の細かいところ**: 項目ごとに「パラメータのタブ」「項目」「内部名」「前の値 → 新しい値」を出す。**単位は出していない**（Houdini の ParmTemplate に単位の情報が無く、記録にも無い。推測で書かない）。
- **どの部分を作業するかを、冒頭に**: 各手順の先頭に「【作業する部分】/obj/tornado の中に、新しいノード「Attribute Wrangle」（名前: vortex_points）を作る」「…/vortex_points のパラメータを変える」などを出す（`work_headline`）。
- **「どんな目的で、このノードを使っているか」**
  - 元データ: 手順ごとの記録には、目的が無い。手順書（.md）の「作る前に: 使うノードと、できること」の節に、「ノード名（タイプ）: 目的」の一覧がある。これを読み取って、手順の「このノードの目的」に出す（`purposes_from_markdown`。実在の手順書の形式で確認）。以前の案内データも、同名の .md があれば読み直して足す。
  - 足りない分: その節に載っていないノードや、節が無い手順書では、目的は空（作らない）。**生成側（`houdini_tools._step_guide`）が、手順の記録に `purpose` を入れれば、そちらを優先して使える形にした**（`build_guide` が `guide["purpose"]` を読む）。
- **状態**: 一部（単位は出せない。値・メニュー・場所・目的は完了。目的は、手順書に載っているノードだけ）

### 4. チュートリアル生成後は、自動で Guide タブを最新にする
- **前**: 案内データは、**保存したとき**だけ書かれ、生成が終わっただけでは Guide タブは何も変わらなかった。切り替えもなく、利用者は気づけなかった。
- **後**: 生成完了（`tutorial_view._on_done`）で、結果から手順をメモリ上で組み立て、Guide タブの先頭に「（生成直後・未保存）…」として読み込み、**Guide タブへ切り替える**。ステータス文にも「Guide タブに切り替えて、最新の手順を読み込みました」と出す。
  - 切り替えない設定（Guide タブの「生成が終わったら、自動でこのタブに切り替える」。覚える。既定はオン）のときは、タブ名を「Guide ●」にして印を付け、開くと戻す。
  - 保存（単発）では、未保存の手順を保存したものに置き換える（切り替えはしない。保存操作中のため）。3段階連続生成は、保存後に最後に保存した手順を読み込んで切り替える。
  - タブの切り替えは、`rag_chatbot.py` を変えずに、Qt の親をたどって `QTabWidget` と Guide を見つけて行う（`guide_view.locate_in_tabs`）。
  - テスト: `WidgetFlowTest`、`TutorialViewHookTest`（生成完了の処理 → 切り替え、設定オフの印、保存で置き換え、例外を出さない）。
- **状態**: 完了（Qt の画面なしでの確認。実機のタブ構成は未確認）

## 未対応・要確認（ユーザーの判断・実機確認が要るもの）
- **実機で確かめてほしいこと**（偽物では確認できない Houdini の API）:
  1. `editor.setCurrentNode(node)`、`hou.ui.paneTabOfType(type, index)`（複数のペイン）、`PaneTab.isPin()/setPin(False)`（パラメータ画面のピン）が、使っている版（22.0.x）で動くか。どれも、無い・失敗したときは飛ばす書き方にしてある。
  2. 生成したサンドボックスが残っている状態で、「案内する場所」の3つの選択が、期待どおりに動くか。特に、自動のとき、自分の `/obj/geo1` が別の用途のものでも、種類（`geo`）が合えばそれを示す。
  3. 3の「どの階層にいるか」の更新（1.5秒ごとのタイマー）が、重くないか。
- **目的の説明**: 手順書の「使うノード」の節に載っているノードだけ。節が無い・書式が違う手順書では、出ない。確実にするには、`houdini_tools._step_guide`（他の担当のファイル）が、手順ごとに `purpose` を記録するか、生成のプロンプトで、すべてのノードの目的を「使うノード」の節に書かせる。
- **メニューの表示名**: 画面で出すときに、ノード（無ければノードの種類）から引く。生成時（ノードが手元にあるとき）に `houdini_tools._step_guide` から `guide_mode.parm_value_info(template)` を呼んで、案内データに入れておくと、サンドボックスを消したあとも、確実に引ける（いまは、種類から引くので、消したあとも多くの場合は引ける）。
- **単位**: 記録にも ParmTemplate にも無いので出していない。出すなら、生成側でパラメータ名ごとの単位を持つ必要がある。
- **記録時の切り捨て**（`houdini_tools.py`）: 値60文字・前の値40文字・つなぐ線12本。長い値は、画面で断るだけ。直すなら、生成側。
- **パラメータ画面内のタブ・項目の強調**: 文言のみ（上の2）。
- **ほかのタブとの並べ表示**: 別ウィンドウまで。パネル全体の分割は未対応（上の5）。
- **ショートカット**: 表は変えていない。「消す」手順の「Delete キー」の文は、以前からのもの。公式ドキュメントで、ノードの削除のキーとしては確認できていない（表には載せていない）ので、気になるなら、右クリックのメニュー（確認できたもの）に直す。
